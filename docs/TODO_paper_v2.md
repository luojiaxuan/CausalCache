## P1 — 决定性实验:HGKV 到底有没有用

这是整篇论文的存亡点。若 HGKV 在闭环上确实无贡献,则它在方法叙事中的地位必须

**设计**:同批、同时间窗、多轮(≥3),四臂:

| 臂 | 说明 |

## P2 — HGKV 训练方式的三个可疑点(用户诊断,按嫌疑排序)

HGKV 改变的是"GUI-Owl **怎样使用**历史图片",理论上应当有用。现在不起作用,
候选原因:

### (a) 训练与部署的 k 不匹配 —— **已证否,不要再做**

假设是"训练只教 k=1、部署走到 k=4 导致失配"。按 k 分层实测(68,849 个共同集合,
`data/results/hgkv_k_stratified_v1`)**效应完全不随 k 衰减**:

| k | n | A(S) |
|---|---|---|
| 0 | 3,358 | +0.00917 |
| 1 | 38,825 | +0.01191 |
| 2 | 25,877 | +0.01256 |
| 3 | 789 | +0.01241 |

**真正的问题是目标函数允许"均匀抬升"充数。** k=0 表示集合恰好就是 Recent-|S|,
适配器本应中性,实测却有 +0.00917 —— 占 k=1 总效应的 **77%**。对一般远端帧的
选择性只有 **+0.0027**,比对训练时挖出的 witness 帧(+0.0224)小 **8.2 倍**。

两个漏洞:

- **漏洞 1:drift cap 太松。** ε=0.02 是 gain margin m=0.01 的两倍,"贴着 cap 加均匀
  抬升 + 一点点选择性"同时满足 $[m-A_s]_+=0$ 与 $[|A_r|-\epsilon]_+=0$,是最省力解。
  **← 正在修(见下)**
- **漏洞 2:目标是三选一,不是排序。** 每组只对比 relevant/recent/wrong 三个臂,
  适配器**从未被要求在多个看起来都合理的远端帧之间分高下**,而那正是部署时的任务。

  **已核实的语料事实**(`desktop-did-corpus-v4`,10,905 条 = 2,181 组 × 5 臂
  R0/RA/S0/SA/WA,752 episode / 963 决策点,budget 1/2/4 = 962/756/463):
  - **2,181 个 SA 臂全部 `k_replaced=1`** —— "训练只教 k=1"属实,
    但 k 分层已证明效应不随 k 衰减,所以这不是失效原因,**不要去补 k≥2**;
  - 每组只有**一个** SA,没有可排序的第二个稀疏候选。

  **改法与成本(可负担,比想象便宜)**:每个决策点补打若干候选帧的冻结分,
  拿真值边际做组内排序目标。约 963 决策点 × ~10 候选 ≈ **1 万次教师强制前向**
  (S0 臂已覆盖其中被挖出的那个),四卡一小时内可完成;
  训练侧每组前向数从 5 增到 5+N,按 N=4 约 1.8×。
  **等 v6 收紧 cap 的结果落地后再决定是否投入**——若 cap 已能把均匀成分压下去
  且选择性未塌,排序损失是锦上添花;若选择性一起塌了,排序损失才是必须项。

**漏洞 1 的修复(进行中)**:v6 三臂收紧 ε —— tightcap 0.002(m/5)、
midcap 0.005(m/2)、nogain 0.002 且 gain 权重归零。
判据是 held-out 上 `adapter_on_recent`(v4 = +0.0088)显著变小,
**而 `did_select`(v4 = +0.0224)不能一起塌掉**——塌掉说明 cap 收过头。

> **首轮三臂作废**:误用 `desktop-did-corpus-v1`(sha `e872828e`),v4 基线用的是
> `desktop-did-corpus-v4`(sha `167009bc`)。config 对齐了、语料没对齐,单变量归因
> 不成立,已按 corpus-v4 重跑。教训见 `code/runscripts/README.md` 第九条。

### (b) LoRA rank 太小

当前 r=8、α=16。相对 4096 维隐层,秩 8 的 K/V 残差表达力可能不足以编码
"这张历史图该被怎样读"。

修法:r=32/64 对照,同一门控与 DiD 目标。成本:重训 + 离线门控,数小时。

### (c) 只挂 last 8 层

信息在浅层就被路由了,只改最后 8 层可能太晚。已有一次 last-36 的尝试
(`desktop_did_v5_gated36_*`),离线选择性更好但闭环仍无差别——不过那次是与
门控/无门控对照,**没有与 frozen+selector 直接同批比过**。

修法:并入 P1 的多臂对照,把 last-36 也放进去。

**优先级:(a) > (b) ≈ (c)。** (a) 有直接证据(26% 的 k=4)、验证便宜、且能解释
"为什么离线门控全过但闭环没有"。

## P3 — OSWorld 改用 max_steps=50

**决定**:以后 OSWorld 以 **50 步**为主设定(对齐 GUI-Owl-1.5-8B-thinking 的口径)。

**缺口**:我们有 selector@50 = **34.07%**(全量 361,全 H200),
但**没有 Recent-4@50**。现有的 recent 臂只跑过 15 步和 30 步。

**动作**:补 Recent-4 @50 全量,且**与 selector@50 同批**(旧的 selector@50 是

(全量,`osworld_sel30_clean_v1`),**在 6.7 倍预算跨度内只浮动 1.4pp**。

## P4 — 主实验预算改用 B=2

**证据**:oracle 相对 recent 锚的可提升空间在 **B=2 是 +0.102**、**B=4 只剩 +0.037**
(`indomain_gap_v1/ROOT_CAUSE.md`)。补充材料的全量预算表也显示总体峰值在 B=2
(+6.8pp)、memory-critical 峰值在 B=4(+8.6pp)。

**B=4 是最难展示选择价值的工作点**:四张 recent 帧已经覆盖了大部分需要的信息。

**动作**:主实验改 B=2 需要重跑 MobileWorld 与 OSWorld 的主对照
(Recent-2 vs selector@B=2)。**建议合并进 P1 的多臂设计**,一次跑完
B=2 与 B=4 两个预算,避免重复占机。

## P5 — 方案 3:视觉 embedding 缓存 selector(免 pass-2)

**目标**:用候选帧 embedding + 当前截图 + 任务目标替代"拟议动作"这个 witness 特征,
从而**免掉 pass-2**,同时突破 28 维手工特征的偏差天花板。

**已完成**:
- 抽取脚本 `code/scripts/extract_frame_embeddings_v1.py`,**27,406 张唯一图片抽完**
  (状态×候选对是 5.3 万,缓存省一半);候选帧与当前帧都覆盖;
- 确认可直接调 `get_image_features`(不走完整 LM 前向),patch 均值池化后 1152 维;
- **架构已实现**:`train_selector_v4_marginal.py --arch visual`。
  1152 → 128 投影后取 $u_c,\;u_q,\;u_c\odot u_q,\;u_c-u_q,\;u_c\odot u_S$
  加三个标量($\cos(e_c,e_q)$、$\cos(e_c,e_S)$、归一化距离),与 28 维 cheap 拼接。
  约 32 万参数,部署只需查表 + 一次 MLP。降维矩阵吃强 weight decay。
- **三臂对照已定**(`code/runscripts/train_selector_v5_visual.sh`):

  | 臂 | witness 来源 | 视觉交互 | 含义 |
  |---|---|---|---|
  | `p_cheap` | 真值目标 | 无 | 现 CausalCache-P 部署塔,**需要 pass-2**,上界参照 |
  | `la_cheap` | last_action 伪目标 | 无 | CausalCache-LA,单遍可算,**要超过的基线** |
  | `la_visual` | last_action 伪目标 | **有** | 方案 3 本体 |

  关键量:`la_visual − la_cheap` = 视觉交互净增益;
  `la_visual − p_cheap` ≥ 0 则 pass-2 可以去掉。

**为什么必须是交互而不是直接拼接**:实测 448 维读出在可加两塔结构下退化成常数
(均值 0.0653 / 标准差 0.0021,比值 31)。单独给 $e_c$ 只说明"这张图长什么样",
判断"它对**现在**有没有用"需要 $e_c$ 与 $e_q$ 出现在同一个乘性项里。

**未完成**:训练与离线验证(仅 development 口径,见下方约束)。

> **坑**:三臂的 `--feature-cache` 必须各自独立。该缓存只按 (edge_count, dim) 判命中,
> 而 p/la 两臂这两项完全相同、只有 witness 四维取值不同——共用会静默复用错误特征。

## 约束与已知事实(避免重复踩)

1. **效用级指标只用于 development**(用户裁定):`replay_gain`、`top1-regret`
   可做模型选择与调试,**不进主结果、不对外声称**。
2. **OSWorld 单轮口径无法分辨 ±4pp**:两个在 98% 的步上动作相同的臂,
   任务级翻转 14.4%。任何单轮 ±4pp 内的差异都不构成证据。
3. **跨轮比较不可信**:同一 Recent-4 臂三个时间窗 32.96 / 30.47 / 29.92。
   所有对照必须同批。
4. **selector 部署侧曾有校准缺陷**(readout 塔缺席 = 常数偏置,预测 100% 为负),
   已用 `--selector-score-offset` 修正;任何阈值/早停判据依赖它。
5. **30 步的 46.7/42.4 是错的**(未跑完的中期数),全量为 35.46/36.01。
   见 `paper/AUDIT_camera_ready_osworld30.md`。
