\begin{abstract}
Long-horizon GUI agents face two coupled bottlenecks under bounded visual
context: a policy trained mainly for the current screen may not know how to use
archived screenshots, while a memory selector cannot learn meaningful values
from a policy that treats history as noise. We introduce \method, a
policy-preserving visual-memory interface for frozen GUI agents. Its
history-gated key/value (\hgkv) adapter adds low-rank residuals only to
restored history-image tokens in the final eight language-model layers and is
structurally bypassed when no history image is present, exactly preserving the
base policy at zero visual-memory budget. We train this interface on
GUI-Odyssey with correct, absent, shuffled, and irrelevant histories, without
ordinary action behavior cloning. On top of the adapted policy, \method
defines success-anchored set utility as the change in likelihood of actions
from successful trajectories when a subset of historical events is restored.
A two-stage selector first learns singleton values from counterfactual \hgkv
readouts, then predicts coalition-conditioned marginal gains and a STOP
decision to handle redundancy and complementarity under at-most-$B$ budgets.
All adaptation and model selection use GUI-Odyssey only; the same checkpoints
are evaluated zero-shot on AndroidWorld and OSWorld. On held-out GUI-Odyssey,
\hgkv improves correct-history over no-history likelihood by $0.1372$ nats per
token, reverses negative sensitivity to shuffled and irrelevant histories, and
preserves no-history logits exactly. \pending{Insert final zero-shot
AndroidWorld and OSWorld closed-loop improvements.}
\end{abstract}

\section{Introduction}

GUI agents accumulate screenshots, actions, text arguments, coordinates, and
interface changes over many decisions. Retaining every screenshot is expensive
and can distract a multimodal policy, whereas replacing the entire trajectory
with text summaries removes exact visual evidence such as toggle state,
layout, transient values, and spatial correspondence. A practical agent must
therefore decide which historical events remain available in high fidelity
\citep{lu2025guiodyssey,zeng2026mementogui,shi2026androtmem}.

Most memory controllers address only the selection problem. They retain recent
events, retrieve visually similar screenshots, or learn salience from task
supervision \citep{zeng2026mementogui,shi2026androtmem,liu2026atmem}. These
approaches implicitly assume that the action policy already understands
multiple historical screenshots. Our experiments expose a more basic failure:
a strong frozen GUI policy can change its output when history images are added
while remaining insensitive, or even oppositely sensitive, to whether those
images contain the correct historical evidence. In that regime, a better
selector has little opportunity to improve executable behavior because the
selected evidence is not reliably consumed.

Naively fine-tuning the whole policy is not a clean solution. Full-layer
adaptation simultaneously changes current-screen understanding, action syntax,
coordinate grounding, and termination behavior. It can therefore improve
teacher-forced history sensitivity while overwriting the cross-platform action
prior that made the base policy useful in the first place. The desired module
should instead satisfy three behavioral conditions:
\begin{enumerate}
    \item with no restored screenshot, it exactly recovers the frozen policy;
    \item with irrelevant or corrupted history, it learns to ignore the added
    evidence;
    \item with correct and useful history, it may change the action distribution
    toward successful behavior.
\end{enumerate}

\method implements this separation in two stages. First, a history-gated KV
adapter modifies only the key and value projections of historical image tokens
in the final eight language-model layers. The current screenshot, instruction,
summary text, and generated action tokens remain on the frozen path. Second, a
selector is trained only after the history interface is frozen. Its supervision
comes from controlled restoration interventions: for an action observed in a
successful trajectory, we measure how restoring a candidate event or event set
changes the adapted policy's action likelihood relative to the frozen
no-image baseline.

The selector is explicitly interaction-aware. Singleton values are useful for
the first choice, but are not additive: two individually useful events may be
redundant, and individually weak events may be complementary. \method therefore
uses a lightweight set-conditioned marginal selector that repeatedly scores
remaining candidates given the already selected set and may stop before
exhausting the budget.

Our contributions are:
\begin{itemize}
    \item a policy-preserving \hgkv interface that learns to use visual history
    while guaranteeing exact no-history parity with the frozen GUI policy;
    \item success-anchored restoration supervision that measures the value of
    restoring high-fidelity GUI events for an adapted policy;
    \item an \hgkv-aligned two-stage selector that models conditional marginal
    value, event interactions, and at-most-$B$ stopping;
    \item a benchmark-external training protocol in which the adapter and
    selector are selected only on GUI-Odyssey and evaluated zero-shot on full
    AndroidWorld and OSWorld rosters.
\end{itemize}

\section{Related Work}

\paragraph{Visual GUI agents and benchmarks.}
Screenshot-based GUI agents increasingly learn grounding and action prediction
directly from pixels, including CogAgent, SeeClick, ShowUI, and GUI-Owl
\citep{hong2024cogagent,cheng2024seeclick,lin2025showui,xu2026mobileagent35}.
AndroidWorld provides dynamically instantiated mobile tasks with executable
success checks \citep{rawles2025androidworld}, while OSWorld evaluates agents in
real desktop applications \citep{xie2024osworld}. GUI-Odyssey supplies
cross-application mobile trajectories and serves as our only adaptation and
selector-training source \citep{lu2025guiodyssey}. We use GUI-Owl-1.5-8B as the
frozen cross-platform base policy \citep{xu2026mobileagent35}.

\paragraph{Long-horizon GUI memory.}
GUI-Odyssey couples cross-app trajectories with a history resampler that attends
to prior screenshots \citep{lu2025guiodyssey}. MementoGUI learns multimodal
memory writing, compression, and retrieval operators
\citep{zeng2026mementogui}. AndroTMem retrieves causally linked anchor states
from interaction histories \citep{shi2026androtmem}. These systems establish
that long-horizon GUI control benefits from selective memory. \method focuses
on a complementary bottleneck: before selecting historical images, the policy
must be trained to interpret them without losing its original action
capabilities.

\paragraph{Interventional memory value.}
Recent work studies memory through controlled interventions or active state
influence \citep{srivastava2026cmi,liu2026atmem}. Our intervention is narrower
and executable: every event always retains the same low-fidelity record, while
a selected event additionally exposes exactly one archived post-action image.
The resulting score is a policy-specific behavioral surrogate rather than an
environment-level causal effect. Coalition-conditioned marginals are related to
cooperative-game attribution \citep{shapley1953value}, but our goal is not to
estimate a generic Shapley value; it is to train a deployable budgeted selector
for a fixed GUI policy.

\section{Problem Formulation}

At decision $t$, the agent receives instruction $g$, current observation
$x_t$, and history
\begin{equation}
H_t=\{e_1,\ldots,e_{t-1}\}, \qquad
e_j=(x_j,a_j,x_{j+1},\delta_j),
\end{equation}
where $\delta_j$ is an optional deterministic UI delta. Each event has a
compact low-fidelity record $\tilde e_j$ and an archived high-fidelity
post-action screenshot $v_j$.

For a candidate set $S\subseteq\{1,\ldots,t-1\}$, let $X_t(S)$ denote a
mixed-fidelity prompt that includes $\tilde e_j$ for every event and additionally
includes $v_j$ only for $j\in S$. The current screenshot is always included.
The selector chooses
\begin{equation}
M_t\subseteq\{1,\ldots,t-1\}, \qquad |M_t|\leq B,
\end{equation}
where $B$ is the number of restored historical screenshots. Unselected events
are not deleted; they remain available through their summaries and external
archive.

We separate two goals. The history interface should improve the action policy
when useful visual evidence is present while preserving the frozen policy at
$B=0$. Given that interface, the selector should maximize executable success
under a fixed budget. Because full closed-loop counterfactual labels are
prohibitively expensive, selector training uses a dense success-anchored action
surrogate and closed-loop benchmarks provide final validation.

\section{CausalCache}

\subsection{Policy-Preserving History-Gated KV Adapter}

Let $h_l$ be the input to layer $l$'s attention projections. In the last eight
language-model layers, \method adds rank-8, $\alpha=16$ low-rank residuals
\citep{hu2022lora} only to key and value projections:
\begin{equation}
\begin{aligned}
K_l &= W^K_l h_l + M_{\mathrm{hist}}\,\Delta W^K_l h_l,\\
V_l &= W^V_l h_l + M_{\mathrm{hist}}\,\Delta W^V_l h_l.
\end{aligned}
\end{equation}
$M_{\mathrm{hist}}$ is a token mask that is true only for restored historical
image tokens. It excludes instruction tokens, event-summary text, the current
observation image, and action tokens. The mask is constructed fail-closed from
the multimodal token-type sequence and per-image patch geometry; any mismatch
between declared images and encoded image blocks aborts the forward pass.

When no history image is restored, the adapter context is absent and the
projection hook returns the original module output without computing a
residual. Thus
\begin{equation}
\adapted(\cdot\mid X_t(\varnothing))
=\base(\cdot\mid X_t(\varnothing))
\end{equation}
up to bitwise equality in our implementation. During autoregressive generation,
the adapter acts only during the prompt prefill; its historical K/V increments
are then carried by the ordinary KV cache, while decode tokens bypass the
adapter.

\subsection{Counterfactual History Supervision}

For a successful GUI-Odyssey decision with target action $a_t^*$, we construct
four prompts with the same target:
\begin{itemize}
    \item \textbf{correct}: the selected event summaries and images are aligned;
    \item \textbf{B0}: no historical screenshot is restored;
    \item \textbf{shuffled}: the same restored slots receive permuted images;
    \item \textbf{irrelevant}: restored slots receive donor images from another
    trajectory.
\end{itemize}
Let $\ell_c,\ell_0,\ell_s,\ell_i$ be the mean target-token log likelihoods under
these variants, where $\ell_0$ is computed by the frozen policy and detached.
We train only the \hgkv parameters with
\begin{equation}
\begin{aligned}
\mathcal L_{\mathrm{gain}} &= [m-(\ell_c-\ell_0)]_+,\\
\mathcal L_{\mathrm{rank}} &= [m-(\ell_c-\ell_s)]_+
+[m-(\ell_c-\ell_i)]_+,\\
\mathcal L_{\mathrm{ignore}} &=
\operatorname{SmoothL1}(\ell_s,\ell_0)
+\operatorname{SmoothL1}(\ell_i,\ell_0),\\
\mathcal L &= \mathcal L_{\mathrm{gain}}+
\mathcal L_{\mathrm{rank}}+\mathcal L_{\mathrm{ignore}}
+\lambda\lVert\Delta W\rVert_2^2.
\end{aligned}
\end{equation}
We use $m=0.01$, $\lambda=10^{-4}$, and no ordinary action cross-entropy. This
prevents GUI-Odyssey from becoming a new action-imitation curriculum for the
base policy; it supplies only comparative supervision about when historical
visual evidence should help or be ignored.

\subsection{Success-Anchored Set Utility}

After freezing the history adapter, we define the utility of a restored set $S$
as
\begin{equation}
U_t(S)=\frac{1}{L}\sum_{k=1}^{L}
\log \adapted\!\left(a^*_{t,k}\mid a^*_{t,<k},X_t(S)\right)
-\ell_{0,t}.
\label{eq:uact}
\end{equation}
Because of exact B0 parity, $\ell_{0,t}$ may be computed by either the frozen or
history-gated policy under $X_t(\varnothing)$. The conditional marginal of
candidate $j$ given an already selected set $S$ is
\begin{equation}
\Delta_t(j\mid S)=U_t(S\cup\{j\})-U_t(S).
\label{eq:marginal}
\end{equation}
Unlike a fixed event score, Eq.~\ref{eq:marginal} preserves redundancy and
complementarity. Every utility used for formal selector evaluation is obtained
by rerunning the complete selected set; we never report a sum of singleton
gains as the utility of a multi-event coalition.

\subsection{HGKV Counterfactual Readout Features}

The selector should use the same interface through which the policy reads
history. For each candidate and each adapted layer, we capture the frozen
decision query $Q_l$ at the final prompt token, the candidate's frozen history
keys and values $(K^0_{l,j},V^0_{l,j})$, and the adapter increments
$(\Delta K_{l,j},\Delta V_{l,j})$. We then compute a differential readout
\begin{equation}
\Delta r_{l,j}=
\operatorname{Attn}(Q_l,K^0_{l,j}+\Delta K_{l,j})
(V^0_{l,j}+\Delta V_{l,j})
-
\operatorname{Attn}(Q_l,K^0_{l,j})V^0_{l,j}.
\end{equation}
This calculation is taken at the projection outputs where the adapter is
injected. It is a lightweight counterfactual feature, not an exact replay of
the full normalized and rotary-positioned attention block. For each layer we
concatenate the mean-head readout difference and per-head norms, producing 160
features; eight layers yield a 1,280-dimensional candidate representation.
Event features can be cached after extraction, while the current decision is
encoded once per state.

\subsection{Two-Stage Budgeted Selector}

\paragraph{Stage 1: singleton scorer.}
A shared $160\!\rightarrow\!64$ layer encoder with learned attention over the
eight adapted layers maps each candidate to an embedding. Four heads predict
singleton gain, within-state rank, positive gain, and a state-level STOP score.
Training combines SmoothL1 regression, pairwise logistic ranking, positive-label
binary cross entropy, and STOP binary cross entropy. Stage 1 selects the first
event, supplies the independent marginal baseline, and initializes Stage 2.

\paragraph{Stage 2: set-conditioned marginal scorer.}
Permutation-invariant set models commonly aggregate elements through pooled or
attention-based encoders \citep{zaheer2017deepsets,lee2019settransformer}.
Our Stage 2 uses a deliberately lightweight variant: candidate embeddings
already encode the current decision through their \hgkv readouts, one
self-attention block contextualizes selected-event embeddings, and one
cross-attention block maps remaining candidates to that selected context. A
remaining-budget embedding conditions marginal, rank, positive, and STOP heads.
It is trained from real conditional edges such as
$U(\{i,j\})-U(\{i\})$ and $U(\{i,j,k\})-U(\{i,j\})$, generated along fixed
shortlist, recent, greedy, and small-beam paths rather than by enumerating the
full power set.

At inference, Stage 1 makes the first choice; Stage 2 then repeatedly compares
the best remaining candidate with STOP:
\begin{algorithm}[t]
\caption{At-most-$B$ HGKV Set-Conditioned Selection}
\label{alg:selector}
\begin{algorithmic}[1]
\REQUIRE Candidate features $E$, budget $B$
\STATE $S\leftarrow\varnothing$
\STATE Score first events and STOP with Stage 1
\IF{STOP outranks every event}
    \RETURN $S$
\ENDIF
\STATE Add the highest-ranked event to $S$
\WHILE{$|S|<B$}
    \STATE Predict $\widehat\Delta(j\mid S)$ and STOP with Stage 2
    \IF{STOP outranks every remaining event}
        \STATE \textbf{break}
    \ENDIF
    \STATE Add the highest-ranked remaining event to $S$
\ENDWHILE
\RETURN $S$
\end{algorithmic}
\end{algorithm}
The deployed V1 selector supports $B\in\{1,2,4\}$. We separately use $B=8$ as
a large-memory policy stress test.

\section{Experimental Setup}

\subsection{Training and Model Selection}

All adapter and selector parameters are trained and selected only on corrected
GUI-Odyssey trajectories \citep{lu2025guiodyssey}. Coordinates are interpreted
in their native normalized range; system-button actions and terminal states are
retained, and incomplete trajectories are excluded. Splits are
trajectory-disjoint. The history adapter is selected only from GUI-Odyssey
history-use metrics. The Stage-1 and Stage-2 selectors use train-episode
GroupKFold for epoch selection, followed by a full-train refit and one read of
the GUI-Odyssey development set. No AndroidWorld or OSWorld task is used to
choose an architecture, checkpoint, loss, threshold, or budget.

\subsection{Policies and Memory Baselines}

The frozen policy is GUI-Owl-1.5-8B-Instruct
\citep{xu2026mobileagent35}. We compare:
\begin{itemize}
    \item \textbf{Frozen}: no trainable policy adapter;
    \item \textbf{Full-layer LoRA}: the strongest corrected GUI-Odyssey baseline,
    modifying all language-model Q/K/V/O projections \citep{hu2022lora};
    \item \textbf{Top-8 ungated KV}: an architecture-matched control using the
    same layers, K/V targets, rank, and alpha as \hgkv but without token gating;
    \item \textbf{HGKV}: the proposed policy-preserving history interface.
\end{itemize}
Memory baselines are Random, Recent, OCR/RGB Similarity, the Stage-1 marginal
selector, and the Stage-2 set-conditioned selector. Similarity averages OCR
token-set Jaccard and a joint RGB-histogram cosine score. Every method receives
the same low-fidelity history and the same number of restored images.

\subsection{Zero-Shot Benchmarks and Metrics}

AndroidWorld \citep{rawles2025androidworld} is evaluated on all 116 task
templates with two fixed dynamic instances per template. We average the two
instances within each template and report template-macro success, with 10,000
template-clustered paired bootstrap replicates. The primary headline includes
all templates; a predefined 107-template action-compatible view is a
sensitivity analysis. OSWorld \citep{xie2024osworld} uses the fixed 361-task
no-Google-Drive roster and reports mean normalized task score. Infrastructure
failures remain in an intention-to-treat denominator unless the environment
fails before any policy step under a policy-agnostic void rule.

For policy adaptation we report $B=0$, Recent-4, and Recent-8. For selection we
hold \hgkv fixed and report $B\in\{1,2,4\}$. Offline selector metrics include
true selected-set utility, recovery relative to an exact or declared
approximate oracle, regret, STOP rate, and latency.

\section{Ablations and Analyses}

The main ablations are intentionally factorized rather than forming a
policy--selector Cartesian product. Policy-use ablations hold Recent memory
fixed and compare Frozen, full-layer LoRA, ungated top-8 KV, and \hgkv.
Selection ablations hold \hgkv fixed and compare Recent, Similarity, singleton
marginal, and set-conditioned selection. Additional analyses include adapter
depth and rank, removal of gain/rank/ignore losses, selected top-$B$ versus
bottom-$B$, wrong-event replacement, summary--image mismatch, and temporal
reversal. We also stratify results by trajectory length, app, and the gap
between Recent and oracle memory.

\section{Limitations and Claim Boundary}

The success-anchored utility in Eq.~\ref{eq:uact} is a dense teacher-forced
surrogate, not a direct long-horizon return. Its value must ultimately be judged
by closed-loop success. The word ``causal'' in \method refers only to a
controlled intervention that restores selected screenshots while holding the
remaining prompt fixed; we do not identify environment-level structural
causality or learn a world model.

Our zero-shot claim concerns \method adaptation: neither the adapter nor the
selector uses AndroidWorld or OSWorld data for training or model selection. We
cannot guarantee that the pretrained base policy never encountered related
data. GUI-Odyssey is mobile-only, so OSWorld evaluates whether the learned
history interface transfers beyond its adaptation platform. The current HGKV
adapter still raises the likelihood of some wrong-history variants, and the
set-conditioned selector is partly motivated by this limited content margin.
Finally, the current selector supports budgets through four restored events;
$B=8$ is evaluated only as a policy-level memory stress test.

\section{Conclusion}

\method separates learning to use visual history from learning which history to
show. A token-gated KV adapter adds a history interface to a frozen GUI policy
without changing its no-history behavior. Success-anchored restoration labels
then supervise a selector whose later choices condition on the already selected
set and may stop early. The resulting design isolates the value of historical
evidence from generic policy fine-tuning and enables one GUI-Odyssey-trained
system to be evaluated zero-shot across mobile and desktop environments.
