# 记忆控制器线的故事(汇报稿,截至 2026-09-04 19:50 PT;结果段随夜间实验滚动更新)

> 状态标记:【已测】= 数据在盘上可复现;【在跑】= 今夜出;【设计】= 已预注册未执行。

## 0. 一句话

**GUI agent 能从"检索到的历史截图"里拿到多少收益,取决于它训练时见过什么样的历史布局;
因此在冻结 agent 上做的记忆检索评测,不能外推到联合适配的系统。**

这句话是外审(GPT-5.6 Pro)帮我们收敛到的可辩护版本。我们最初的说法是"训练造出了利用非连续帧的能力",
被驳回——冻结模型本来就会用对的帧,变的是**收益**不是**能力**。

## 1. 为什么这件事值得说

记忆/检索方向的论文很拥挤,绝大多数的实验形态是:**冻结一个 agent,外挂一个检索器,报增益**。
如果收益本身是被 agent 的训练历史布局决定的,那这一整类实验测到的是**各自 backbone 的训练留痕**,
而不是方法的高低。这对领域是一条方法论级别的警告,而不是又一个 +2 个点的方法。

## 2. 证据链

### 第一章:冻结口径下,记忆余量随"喂什么历史"和"喂给谁"剧烈变化 【已测】

**(a) 同一个模型,只改协议,余量差五倍。** UI-Venus-2-9B(2026-08,Qwen3.5-9B 底座),同一批状态,
只改是否保留它自己写的文本推理轨迹:

| 口径 | 仅当前帧 | 最近两帧 | 随机两帧 | ∃正确帧对 | oracle − recency |
|---|---|---|---|---|---|
| **保留**文本推理轨迹(部署条件,396 状态) | 90.4% | 91.9% | 89.0% | 97.7% | **+5.8pp** |
| **去掉**文本推理轨迹(同批状态,70 状态) | 37.1% | 55.7% | 46.0% | 85.7% | **+30.0pp** |

保留文本轨迹时,**72% 的步在全部 23 种历史图组合下输出同一个动作**——记忆已由文本承载,给不给
截图都一样。这就是"冻结口径会测出地板"的直接证据。

**(b) 同一个协议,换个模型,行为敏感度差数倍。** 两个模型都在**部署条件**(保留各自的文本历史)下,
**参考动作均来自各自底座自己的 rollout**(自一致口径),未见任务模板:

| 冻结模型 | 对上下文不敏感的步 | 仅当前帧 | 最近两帧 | ∃正确帧对 | oracle − recency | n |
|---|---|---|---|---|---|---|
| UI-Venus-2-9B | **72%** | 90.4 | 90.4 | 98.5 | +8.1pp | 136 |
| GUI-Owl-1.5-8B | **13.9%** | 63.0 | **54.6** | 71.3 | +16.7pp | 108 |

两个读法:

1. **记忆选择的可得空间是模型的属性,不是方法的属性**:同样的考场、同样的协议、同样的指标,
   Venus 有 72% 的步无论给哪几张历史图都输出同一个动作,GUI-Owl 只有 13.9%。**在谁身上做检索实验,
   决定了你会得出什么结论**。
2. **GUI-Owl 上「给两张最近帧」(54.6)比「一张历史图都不给」(63.0)更差**——它的官方默认历史窗
   在未见模板上是负资产。

**参考动作偏置的自查与修复(2026-09-04 16:30–18:20 PT)**:GUI-Owl 最初那批状态取自 `traj_*` 历史目录,
参考动作出自 iter_50 / iter_86 等**联合训练后代**,而 Venus 的参考来自它自己的 rollout,两者绝对值不可并列。
已用底座 GUI-Owl 重跑 117 题 rollout 取得自一致参考后重测。对照(未见模板):

| GUI-Owl 参考来源 | 仅当前帧 | 最近两帧 | ∃正确帧对 | oracle − recency |
|---|---|---|---|---|
| 微调后代(有偏,n=1052) | 51.0 | 43.6 | 59.6 | +16.0pp |
| **底座自身(自一致,n=108)** | **63.0** | **54.6** | **71.3** | **+16.7pp** |

偏置确实存在且方向如预期(绝对值整体抬高约 12pp),但**两个关键结论不变**:oracle 减 recency 从 +16.0 到
+16.7 几乎不动;「最近两帧差于不给图」不但仍然成立,差距还从 7.4pp 扩大到 8.4pp。**该发现不是标注偏置的产物**。

**指标定义(这张表与第一章其余数字通用)**:benchmark = MobileWorld GUI-only(117 题 = train 78 +
heldout 39);单位是**状态**不是任务;指标是**步级动作复现率**——把同一步的下一个动作在 23 种历史截图
组合下各贪心解码一次,与该轨迹当时执行的动作做等价类匹配(点击类坐标在 0–999 网格上距离 ≤60,
文本类小写相等或子串,其余参数需一致)。**这不是任务成功率**,与 MemGUI-Bench Pass@1 11.7% 或
MobileWorld 任务成功率不是同一量纲,不可互比。

### 第二章:配对的历史布局干预 【在跑】

三臂 SFT,同一批 442 条成功轨迹、15,473 个状态、**目标动作与文本历史逐字节相同、图像张数相同**,
只改是哪两张历史帧:

| 臂 | 平均帧龄(中位) | 两帧间距(中位) | 与谁比、隔离什么 |
|---|---|---|---|
| RECENCY | 1.5 | 1.0 | 官方默认布局(基线) |
| OLDER | 10.5 | 1.0 | 对 RECENCY → **帧龄**的作用 |
| RANDOM | 10.5 | 6.0 | 对 OLDER → **非连续性**的作用(帧龄已配平) |

OLDER 臂是外审要求加的:没有它,RANDOM 的增益可以被解释成"只是看了更老的帧"。发射前脚本逐条
断言三臂除 `keep_frames` 外完全一致(实测 86.5%/88.9% 的样本真的不同),训练超参、种子、优化器、
图像 token 预算、帧顺序全部配平并写成配置指纹存档。

**主指标是固定选择器下的交互效应**(外审改判,取代"每状态取最优对"的口径):

`I = [V_RANDOM训(q) − V_RANDOM训(recency)] − [V_RECENCY训(q) − V_RECENCY训(recency)]`

q 是不依赖被评测模型的固定选择器,跨臂相同,所以测的是**策略适配**而不是选择器好坏。四个绝对值
(无图 / recency / q / 无关历史)全部报——只靠交互为正而 recency 掉了不算证据。

**预注册判据(数据落地前写定,三条同时满足才算成立)**:
1. 交互效应 I 在**未见任务模板**上显著为正;
2. RANDOM 臂的绝对动作正确率不低于 RECENCY 臂(排除"只是 recency 掉了");
3. 无关历史对照上 RANDOM 臂不显著更差(排除"只是更容易被无关内容带偏")。

### 第三章:收益侧 —— 动态 B 的记忆控制器 【设计】

如果第二章成立,控制器才有真正的空间。控制对象是**动态 B**:文本历史恒定保留,平时 B=0 不存图,
只在需要时才取 B 张。现有数据已经把靶子量出来了(Venus,未见模板):恒 B=0 与恒 recency-2 打平
(91.8% 对 91.0%,即**每步花两张图的默认设置平均什么也没买到**),而 oracle 门控只在 10% 的步花预算
就能到 99.3%,同预算的随机门控拿不到任何东西。收益既是质量也是效率。

## 3. 现在的证据强度,以及我不会说的话

- 第一章是**已测**的,口径与样本量都在文档里,可复现。
- 第二章今夜出;**没出之前,我们不主张因果**。§10 那个"联合训练后帧敏感度 +0.068(CI 排除零)"的
  旧结果只是线索——它对比的两个 checkpoint 差了 133 批训练,不是配对对照,不能当证据用。
- 第三方自报数不进我们的表:UI-Venus-2 自报 MemGUI 62.6%、MobileWorld 65.8%;官方榜单最高只有
  M3A 的 32.8%、Qwen3-VL-235B 只有 23.4%;我们按官方协议复现 MobileWorld 得 45.7%,低 20pp。
  对外一律用我们自测的配对数。
- 已知局限,会写进论文:参考动作取自轨迹自身(自一致性偏置);只用成功轨迹(幸存者偏置);
  闭环评测必须用 agent 自己的历史而不是专家前缀。

## 4. 这条线此前的四次失败,以及它们为什么现在有用

| 线 | 结果 | 现在的用处 |
|---|---|---|
| OSWorld RL v1/v2(2026-08) | 20 迭代零效应,selector 与 LoRA 都没训动 | 排除"优化器问题" |
| MobileWorld 联合训练 P1–P4 | 批 100 与 selector-only 两次评测符号相反,效应≈0 | 提供 §10 的帧敏感度线索 |
| 冻结 iter_59 的终局 RL | 22 轮策略几乎没动,70% 的 RLOO 组零对比 | **诊断出"终局回报在地板任务上无信号"** |
| MemGUI 闭环基线 | 两臂各 7/128 | 证实任务级地板,促成换 executor |

四次失败共同指向同一个诊断:**问题不在优化器,在于"记忆给法是否改变结果"这件事本身被 backbone
的训练决定**。这正是现在这条 insight 的来源。
