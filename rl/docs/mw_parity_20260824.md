# MobileWorld 官方对表 + 共享机整改(2026-08-24)

## 0. 一句话现状

MobileWorld 官方 adapter 全默认(`history_n=1` 即 B=0)跑 GUI-only 子集,
**分母 117 题与官方口径完全一致**;中途 107 题判分为 **34.6%**(官方 37.6%),
终值待收。同日因用户质询,修掉三项共享机违规,并用实测吞吐推翻了自己
"加卡提利用率"的判断。

## 1. 对表口径(已核实,非推测)

* 任务总数 **117**,来自 runner 日志 `Task list: ... (117 tasks)`;
  官方 GUI-Only 类目口径,与我们 `--task ALL` 且不加
  `--enable_mcp` / `--enable_user_interaction` 的读法一致;
* 判分**不用 grep**,调官方 `mobile_world.runtime.client.scan_finished_tasks`:
  按任务目录下 `SCORE_FILE_NAME` 存在与否判定完成,`parse_result_file` 取分,
  排除含 `backup` 的目录;
* 中途读数:`judged=107 success=37 rate=34.6%`,对官方 **37.6%** 差 3.0pp
  (≈3.5 题,单次运行方差内);失败样本集中于长程/阅读类
  (`ReadQwen3PaperTask*`、`MastodonOpenAutomatedDeletionTask`)。

## 2. ★ 用户当日质询的三项违规(全部属实)

### 2.1 与他人混用 GPU5

GPU5 上有他人 `claim_gpu:kda-jiaxind` 进程,我的 vLLM 与之同卡。
已迁至 **GPU6 独占**,GPU5 只余他人 1251 MiB。

### 2.2 匿名配置是空指针,`VLLM::EngineCore` 裸奔 14 小时

容器设了 `PYTHONPATH=/data/pyshim`,但**该目录从未创建** —— 全局规则要求的
进程名压平从头到尾没生效。两层修复:

1. 建 `pyshim/sitecustomize.py`,解释器启动阶段(框架导入前)劫持
   `setproctitle` 强制为 `python`;
2. 入口从 `vllm serve` 改为 `python3 -m vllm.entrypoints.openai.api_server`
   —— **`setproctitle` 改不了 `/proc/pid/comm`**,comm 取自 exec 的可执行名,
   这层此前没意识到。

验收:`nvidia-smi --query-compute-apps=pid,process_name` 输出 `python`。

### 2.3 并发被容器数卡死

官方 runner `n_jobs=min(max_concurrency, len(aw_urls))`,我只起 8 台 env 容器
且未传 `--max-concurrency` → 8 路串行。已扩到 **32 台 / 并发 32**。

## 3. ★ 自我推翻:加卡是错的方向(实测数据)

扩并发后实测 vLLM:**generation 25-41 tokens/s、`Running: 0`、
5 分钟 149 请求(0.5 req/s)**。单张 H200 跑 8B 是数千 tokens/s 量级 →
**GPU 实际负载 <1%**。每步约 64 秒中推理不足 1 秒,其余全在 emulator
步进/截图/`step_wait_time=3`。

据此把 DP=2 **缩回单卡,GPU7 归还**。结论写死:
**闭环 GUI 评测的 GPU 是次要瓶颈,靠加卡拉不动利用率;
按全局规则"减少占卡数优先于保持高卡数低利用率"处理。**
(注:全局规则的 80% 利用率硬指标对这类 env-bound 任务不可达,
不应通过占更多卡去"达标"。)

## 5. 当日错误清单(与 §2/§3 不重复)

1. **照抄未核实的挂载路径**:新容器写 `-v /data01/jaxan:/data` 而模型实际在
   `/data04/jaxan/models/`,transformers 把本地路径当 HF repo id 报错。
   教训:迁移服务前先 `docker inspect` 读**现役容器**的真实挂载与参数;
2. **监控读旧路径**(此前已记录过同类):eval 重启后写 `full3.log`,
   监控仍读 `full.log`,持续上报过时的 `succ~37`。已停掉该监控;
3. **容器名模式猜错导致误判**:用 `grep aw-` 找 B2 容器数出 0,
   误以为数据已随容器消失;实际名为 `sglang-omni-jaxan-08241057e*` 等。
   教训:清点自己的资源用**统一前缀** `jaxan`,不要靠记忆中的临时命名。
