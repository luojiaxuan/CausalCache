# AndroidWorld 三臂实验与当日更正(2026-08-23/24)

## 0. 一句话现状

官方 adapter 复现成功(62.7% > 公开单次 56%),干预面收缩为官方 agent 的
**一个函数**;B=4 批次完成其"能复现 + vLLM 提效"的验证使命;**核心科学对照
改在 B=2 上做**,recent-B2 / random-B2 / B0 三臂在 hyper00 进行中。
OSWorld 主实验两条 recent 臂收官(fz 31.0%、r2.0 30.5%)。

## 1. 教义更正:联合 RL,不是"冻结基座 + 外挂选择器"

**用户当日第二次纠正(第一次在 08-22)**:我从
「bridge SFT 出来的 r2.0(30.5%)≈ 冻结基座(31.0%)」推出
「应该不碰基座、把干预放在记忆侧」。**该推理无效**:

* r2.0 是**监督微调**产物,它没增益只说明"用 bridge 合成数据做 SFT 不管用"
  —— 那正是此前造成灾难性遗忘(-13pp)又花力气修回来的路;
* **SFT ≠ RL**。SFT 让 executor 拟合我造的数据分布(与真实桌面存在 mismatch,
  这正是 08-22 否掉 bridge 训练的理由);联合 GRPO 用终局 0/1 在真实环境训,
  executor 与 selector 同时适应,不存在该 mismatch。

**路线口径(不得再滑)**:**selector + executor 全程联合 GRPO,冻结基座仅作
初始化**。退回冻结 executor 只有在"联合 RL 试过且效果不好"时才成立。

**frozen 的唯一合法出现位置**:评测时的 **matched-executor 因果归因**
(同一 checkpoint 固定 executor、只换 selector),那是**评测手段**,
不是训练设计。此前把这两件事混为一谈是错误来源。

## 2. B=4 批次的正确定位:复现验证,非科学对照

用户澄清:B=4 的使命是证明三件事,**均已达成**:

1. **能复现官方结论** —— 官方 adapter 在我方基建 64/102 = **62.7%**,
   高于公开单次 56.0%;
2. **vLLM 提效** —— 116 局从数小时压到 <1 小时;
3. **不是自己手搓 runner** —— 干预面 = 官方 `cut_current_messages` 一个函数;
   53 用例证明 recent 分支与官方逐字节等价;真机验收 4 步成功与原版一致。

因此 B=4 三批 recent≈random(H00偶 57/50、H00奇 58/57、Aries 47/55,
配对 McNemar p=0.69)**不应解读为"选帧不重要"的科学结论** —— 我此前
把它拔高为对课题的挑战,是定位错误。核心对照在 B=2。

## 3. ★ 严重 bug:`--last_image` 不是命令行 flag,导致假数据进入汇报

官方 runner **没有** `--last_image` flag(它是 `GUIOwl.__init__` 构造参数)。
凡带该 flag 启动的进程直接 `FATAL Flags parsing error` 退出。后果:

* B=0 臂从未跑起来;
* **此前汇报的 "recent-B11 7/21 = 33.3%" 系假数据** —— 该臂同样 FATAL,
  统计到的是退出前残留旧文件。**该数字作废**,不得进入任何结论。
  (当时还据此与用户讨论"上下文变多注意力发散",结论虽有独立依据
  ——我们自测 B=4 vs B=2 为 +1.00pp, CI[-1.00,+3.00], p=0.51——但证据链已污染。)

**修法**:预算改由 `CC_LAST_IMAGE` 环境变量注入 agent 构造处
(`patch_budget2.py`;v1 的正则 `GUIOwl\([^)]*\)` 因 `[^)]*` 撞上内层
`GUIOwlWrapper(...)` 的首个 `)` 而把参数插错位置 → TypeError,
教训:**嵌套括号不可用 `[^)]*` 匹配**)。语义 B = last_image - 1。

## 4. 当日错误模式:写了检查却不验证检查本身(6 次)

1. `pgrep -f run_official` 匹配到检查命令自身的 shell → 假"存活"读数;
2. health 判据 grep `READY`,而 `/health` 返回里根本没有该字段 → 空转 15 分钟;
3. smoke 闸门只查进程是否打印 `"complete"` → **0 成功也放行**,让坏配置进正式跑;
4. 就绪探测探 HTTP 5000 端口,而该批容器走 adb 不映射该端口 → 提前发射、全退出;
5. 监控读 `/out/run.log`,补跑批次写 `/out2/` → 误判"停滞"两次;
6. **`--last_image` 被静默拒绝 → 假数据进汇报**(最严重,因为它产出了看似合理的数字)。

**固化纪律**:任何新参数 / 新判据 / 新监控上线前,**必须先在已知结果上验证
它能正确反映**(含故意给错值,确认会报错而非静默通过)。
监控的臂标签已改为**容器自报**(`/out_b2/ARM`),不再靠容器名或端口推断。

## 5. 其它当日更正

* **bind mount 到镜像已有内容的路径 = 隐藏该内容**:把空目录挂到
  `/root/.android` 覆盖了预置 AVD 定义,15 台 emulator 全部 `Unknown AVD name`
  退出。只能重定向"运行期新写入"的路径(`/tmp`)。
* **docker root 是全机配置不该单方面改,但容器写哪由我决定**:用户两次指出
  (Aries、moss)。大写入 bind mount 到数据盘即可,不必碰 daemon。
* **并发必须按实测单位成本反推**:29 台压垮单 vLLM(空响应)、15 台压垮
  Aries CPU(a11y 超时)、24 台叠加未收官主实验压垮 hyper00 adb
  (`clear_app_data` 失败 → 官方 runner 记 failed 且不重试,**会系统性压低所有臂**)。
* **全历史(不裁剪)物理不可行**:每帧约 2584 visual token,32k 上下文
  **约 12 帧即溢出**,而任务动辄 20-30 步。这从反面支持"定额记忆是必需品"。

## 6. OSWorld 主实验(361 官方口径,B=2,50 步)

| 臂 | 成功率 |
|---|---|
| `fz_recent`(冻结基座 + recent-2) | **112/361 = 31.0%** |
| `r2_recent`(bridge SFT r2.0 + recent-2) | **110/361 = 30.5%** |
| `r2_sel` | 360/361,待收 |

不是提升桌面能力**。**注意:这不构成"应冻结 executor"的论据**(见 §1)。

最核心的一对是 `fz_sel vs fz_recent`(同 executor 只换记忆策略),
基准线已钉死 31.0%,待 fz_sel 收官读增益;并按域拆开,重点看 `multi_apps`
(93 题,唯一真正需要跨时记忆的域,r2_recent 在其上仅 11.8%)。
