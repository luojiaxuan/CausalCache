### B1 🟡 selector 容量升级 —— **当前主线**

- **为什么**:欠拟合已被直接证据锁定 —— 在**训练过的** 421 个 winnable 态上

  交互;"单帧边际 68.4% vs 集合边际 36.8%" 就是交互项存在的直接证据。

### B2 🟡 特征信息量探针

- **为什么**:B1 若也拟合不上,病因就不在头而在**特征** —— 144 token 缩略图
  + 均值池化可能已经把判别信息丢了,那要动的是索引遍(提分辨率 / 换池化 /
  取多层),而不是继续换头。**这个探针能把"头太弱"和"特征没信息"分开**,
  不做就会在换头上反复空转。
- **完成判据**:缓存 winnable 态的帧特征,在**训练集**上拟合一个强模型,
  报训练集子集排序准确率。≥0.9 → 特征够用,是头的问题;
  ≈0.6 → 特征本身没信息,转去改索引遍(分辨率 / 池化 / 取多层)。
- **🔧 不需要写新脚本**:这个探针就是 B1 训练器的一组配置 —— 探针只问
  "**有没有任何模型能拟合训练集**",不关心泛化。所以:
  `--feature-cache <cache.pt> --head-arch mlp_pair --use-context
   --pooling mean_max --hidden 2048 --epochs 20 --holdout-frac 0.05
   --learning-rate 1e-4`,然后只读 `report.json` 的 `train_rank_acc`
  (训练后静态复测,不是滑动平均)。**故意让它过拟合** —— 过拟合得起来
  才说明特征里有信息。
- **阻塞**:需要先把特征缓存落盘(`cache_index_features.py`,1 卡约 30 分钟,
  与 B1 共用同一份产物)。
- **成本**:缓存 1 卡 × 约 30 分钟;之后每次拟合纯 CPU / 单卡分钟级。

## G. 路线顺序与 RL 准入门槛(2026-08-09 定)

**顺序**:B 曲线 → selector 结构 → HGKV 对照 → 2×2 交互检验 → 才轮到 RL。
每一步都是**后一步的前提**,不是并列的待办。

### RL 为什么被判作废

它当初的两条立论,现在各自的状态:

| 立论 | 状态 |
|---|---|
| "选帧离散不可导,需要 score-function 估计" | **失效**。枚举给出精确标签,监督排序条件数好得多,而且**远未用尽** —— v4 连训练集都拟合不上(见过的 421 态上界 100%、只做对 51.1%) |
| "selector 与 HGKV 相互影响,需联合优化" | **预设了 HGKV 成立**,而这正是无证据的部分 |

再加 v3 的判据:参数动得很凶(位移 1.557 / 750 优化步)成绩纹丝不动 ——
**瓶颈在表达力不在优化算法**,而 RL 换的正是优化算法。在一个还没学会拟合
标签的头上加 RL,是优化一个没东西可优化的模型。

### RL 重新有资格进来的门槛(满足其一)

1. **监督选帧已饱和**(拟合得上训练集且泛化),但闭环成绩仍显著低于离线
   预测 —— 说明存在只有闭环奖励能修的训练/部署错配;
2. **selector 与策略适配器被证明存在交互**(各自单独有效,组合起来非加性)
   —— 这个用 2×2 离线消融就能测,**不需要 RL**。

两条都不满足时,监督 + 离线标签在成本与条件数上都完胜。

### 「策略读不懂非 recent 帧」这个担心,现有数据的回答

**基本可以排除,但有一个明确上界。** 困难态上 B=2 的 oracle 52.8% vs
recent 24.8% —— 若策略读不懂非最近帧,oracle(选出来的多半不是最近两帧)
应当 ≈ recent,而不是两倍多。**冻结策略确实能用上非最近帧。**

上界:困难态里 **47.2% 是 hopeless**(枚举证明无任何子集可解)。其中多少是
"策略消化不了"、多少是"信息真的不在历史图里",**现有数据分不开**。
而这恰恰是策略适配(HGKV / SFT)唯一可能有价值的地方 —— 选帧在 hopeless
态上按定义无能为力。下条实验就打在这里。

### H1 🟡 HGKV vs 全层 SFT 对照(排队中,等 B1 让出卡)

- **为什么**:HGKV(末 8 层 k/v LoRA,rank 8,65.5 万参数)当初是按
  "便宜 + 像记忆"选的,**从未与全层 SFT 比过**。用户的质疑成立:
  没有这个对照,"为什么是 HGKV 而不是全参微调"在论文里答不出来。
- **为什么打在 hopeless 分层**:那里选帧的贡献**按定义恒为零**,
  信号干净 —— 任何提升都只能来自策略适配,不会与 selector 混淆。
- **🔧 08-09 复核:基础设施已存在,基本是配置工作。**
  `code/scripts/train_success_sft_lora.py` 已支持三种 adapter(`adapter_settings`),
  并有现成配置 `causalcache_desktop_did_{hgkv_v4,full_lora_v3}.json`。
  **而且它带了一个我原设计里缺的对照臂**:

  | adapter_type | 是什么 | 隔离什么 |
  |---|---|---|
  | 冻结 | 0 参数 | 基线 |
  | `history_gated_kv` | 末 N 层 k/v + **restored-history 门控** | 现有主张 |
  | **`ungated_kv_lora`** | **同层位、同 rank,无门控** | **门控机制本身值不值** |
  | `full_policy_lora` | 全层 q/k/v/o | 层位与容量够不够 |
  | (可选)全参 SFT | 80 亿 | 容量上限 |

  **`ungated_kv_lora` 是关键**:它与 HGKV 同层位同 rank、只差门控。
  没有它,"HGKV 有效"里"位置选对了"和"门控起作用了"两件事混在一起,
  答不出"为什么非要门控" —— 而那正是审稿人会问的。

- **⚠️ 必须并排 B=0 对照臂(今天的发现加的硬约束)**:在 hopeless 态上做
  gold 监督,提升可能全部来自**任务 SFT** 而与记忆无关。因此评测要做
  **{冻结, HGKV, ungated, full} × {B=0, recent-2}** 的 2×N:
  若某臂在 B=0 与 recent-2 上提升相同 → 那是任务 SFT;
  只有 recent-2 上的提升**显著大于** B=0 上的,才是"适配让历史变得可读"。
- **⚠️ 目标函数要改**:现有配置跑的是 DiD group loss,#26 要的是
  hopeless 态上的 gold action 监督。adapter 机制可复用,**目标与数据管线要新写**。
- **完成判据**:留出 hopeless 态上,各臂 (recent-2 提升 − B=0 提升) 的配对检验。
  HGKV ≈ 全参 SFT 而参数少两个数量级 → 卖点成立;
  HGKV ≈ ungated → 门控无用,该简化;全参远超 → HGKV 前提死掉。
- **数据量**:hopeless 共 1290 态(约 1030 训 / 260 留出)—— **偏小**,
  LoRA 容易记住而非学会,留出集数字是唯一可信的。
- **成本**:前三臂各 1 卡约 3 小时(含 2×N 评测);全参 SFT 要多卡,等 B 曲线让位。

## E. 已知缺陷(暂不修,但报告时必须披露)

| 缺陷 | 偏差方向 | 为什么暂不修 |
|---|---|---|
| 枚举用剪枝(单帧 top-8 → 组合),非全枚举 | **低估 oracle**(命中率 95.7%,漏约 4.3%) | 全枚举 10 分钟/态,不可承受 |
| 候选 >30 的 state 直接跳过 | **低估长历史场景** —— 而长历史正是"旧帧有用"最可能出现的地方,**对我们不利** | 成本 |
| 缺图的 state 整态跳过(约 11%) | 无方向性(缺图与内容无关),但样本少 11% | 只丢部分候选会让候选池不完整,反而低估 oracle |
| 捕获率跨样本计算(评测无 oracle 臂) | 口径缺陷,不是偏差 | oracle 需枚举,太贵。B 曲线跑完后可在同一批态上闭合 |
| 结论只覆盖 ubuntu 桌面 | 外部效度 | winmac 帧集未处理 |
