# 枚举 oracle 选帧:强基线 + 上界 + 标签(实验契约 v1)

预注册于 2026-08-08,用户裁定"提前做"。本实验**不训练 HGKV**,
只回答一个干净的问题:

> **冻结 policy 不动,只把历史帧换成更好的,步级动作正确率能提多少?**

## 0. 为什么值得优先做(三个产出,一次拿到)

1. **强基线**:冻结 policy + 无 HGKV + 完美选帧。上限低于联合训练(缺 HGKV),
   但它是"选择本身值多少"的干净度量,是后续所有方法的对照;
2. **上界(标尺)**:任何 selector 学到的成绩都可以除以它,得到捕获率。
   v1 时代我们只捕获了 **6.5%** 却不自知,就是因为没有这把尺子在手边;
3. **监督标签**:每个 state 的"最优 B 帧",可直接喂给 selector 做排序学习。

## 1. 纠正一个此前反复出现的错误框架

历史文档多处写"离线增益不迁移闭环",**这个说法不成立**。实测:

| 部署口径 | 模型−锚 | oracle−锚 | 捕获率 |
|---|---|---|---|
| B=2 | **+0.0066** | +0.1019 | **6.5%** |

模型的离线增益只有可得头寸的十五分之一,**这个量级不足以改变动作**,
闭环没反应是应然。加之离线语料(AgentNet/OpenCUA 桌面示范)与闭环
(OSWorld)不同源。**正确表述:我们从未做出足够大的离线增益,
"离线→闭环"这个命题至今未被检验。**本实验的目的之一就是先把离线增益做大,
让这个命题第一次变得可检验。

## 2. 数据

| 项 | 值 |
|---|---|
| 语料 | **AgentNet/OpenCUA 桌面示范**(人类标注,每步有 ground-truth 动作) |
| 起步规模 | `desktop_did_corpus_v1` 的 969 组打通流程 |
| 扩展 | hyper00 `agentnet-frames-v3`(规模更大),流程通过后再扩 |
| **不用 GUI-Odyssey** | 已判 NO-GO,理由与本假设相悖:"Odyssey 上 recent 天然更强且目标 case 稀少"——用它等于自己发烂牌 |
| 候选池 | **该 state 的全部历史帧(含 recent)**,不设 `age ≥ B+2` 之类阈值——去启发式是本实验的要点 |

## 3. 打分指标(容差在这里解决)

**步级正确率** = 动作类型匹配 **且** 坐标误差 ≤ **25px**
(沿用语料里已实现的 `coordinate_tolerance = 25`)。

关键设计:**这个指标不需要可导**。selector 的监督来自"哪个子集得分最高",
标签在离线生成阶段算完;训练时用排序/分类损失。**容差问题被完全吸收进
标签生成,不进损失函数。**(只有后续 SFT HGKV 时容差才会真正咬人,
届时用"容差内则以模型自身输出为目标"的 relabel 方案。)

## 4. 枚举与剪枝

- 全枚举 C(n,2),n≈25 → **300 组/state**,每组一次前向(约 2s)→ 10 min/state,太贵;
- **剪枝**:先固定一个搭档逐个评估单帧(n≈25 次)→ 取 top-8 → 其间全配对
  C(8,2)=28 → 合计 **53 次/state**,省 5.7 倍;
- **剪枝校验(必做,不可省)**:在 **30 个 state** 上同时跑全枚举与剪枝,
  比对命中率。
  - 命中率 ≥90% → 采用剪枝;
  - 否则放大到 top-12(C(12,2)=66,合计 91 次)重校验;仍不达标则全枚举 + 缩小样本。
  - **理由**:旧数据显示单帧边际为正 68.4%、集合边际为正仅 36.8%,
    **两帧间存在交互**,可能存在"单独平庸、合起来很强"的组合被剪枝漏掉。
    漏掉会低估头寸 → 可能误判成"没头寸"而错误终结项目。

## 5. 四臂(缺一不可)

| 臂 | 含义 |
|---|---|
| **oracle-最优2** | 枚举出的最佳组合(上界) |
| **recent-2** | 部署默认基线 |
| **随机-2** | **防自欺的关键对照** |
| **B=0** | 无历史图 |

**随机-2 这一臂是硬要求**:归档里有一条警示——AndroidWorld success-anchor 数据上
"喂正确历史图 vs 喂打乱/无关历史图,差异 ≈ 0","说明它没有稳定使用图像内容"。
若在桌面数据上 **oracle-最优2 ≈ 随机-2**,则该结论复现,**选择无价值,项目终结**。
不设这一臂,我们会把"模型对图像内容不敏感"误读成"选择有效"。

## 6. 预注册判据

| 结果 | 结论与动作 |
|---|---|
| oracle ≈ 随机-2 | 策略不使用历史图内容 → **终结**,负结果入论文 |
| oracle ≈ recent-2 且 > 随机-2 | 有内容敏感度但 recent 已最优 → 选择无头寸,**终结** |
| **oracle >> recent-2** | 选择有真实头寸 → 产出标签,进入 selector 学习阶段,并**以此为分母报捕获率** |

## 7. 之后:闭环检验点(用户裁定,硬要求)

oracle 臂本身**不能部署**(需要 ground truth)。闭环检验的对象是
**用这批标签训出的 selector**:

- **早做、小步做**:selector 训到约 2000 步就先跑一次 **40 任务闭环快测**,
  不等训完整套;
- 若步级正确率涨了但闭环纹丝不动,**先停下追问口径与 benchmark 的决定因素**,
  不要继续加训;
- 闭环判读沿用已标定的噪声口径(同系统重测翻转 11.7%、总数 ±4 任务/120,
  单轮检出下限 ≈9pp),**报点估计必须同时报噪声与检出力**。

## 8. 与联合训练的关系

本实验是**基线与标尺**,不是终点。后续的联合训练(步级 GRPO:
selector 用 score-function 绕过离散、HGKV 走可导 SFT,奖励 = 每步
`log p(ground-truth action)`)上限更高,但必须以本实验的 oracle 为分母
报捕获率,否则会重演 v1"涨了 6.5% 却以为方法有效"的误判。
