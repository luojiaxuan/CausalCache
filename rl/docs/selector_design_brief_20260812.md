# Selector 架构设计简报(供外部方案设计用,自包含)

> 目的:请一个外部模型/专家设计"帧选择器"(selector)的模型架构与训练方案。
> 本文档给出:任务定义、已有数据资产、**已被实验证伪的配置**(不要重新提出)、
> 部署约束、验收口径。所有数字都来自已完成实验,出处为本仓库台账
> `rl/docs/audit_ledger_20260809.md`。

## 1. 任务定义

- **场景**:GUI agent(桌面 ubuntu,AgentNet 语料)逐步执行任务。策略模型是
  **冻结的 GUI-Owl-1.5-8B**(不可改动;下游另有改策略的路线,与本问题无关)。
- **记忆预算**:策略每步的输入 = 任务指令 + 全部历史步骤的**动作文本摘要** +
  **B=2 张历史截图**(全清,每张 2560 视觉 token)+ 当前屏(全清)。
  默认基线取**最近两帧(recent-2)**。
- **selector 的任务**:从该步的候选历史帧集合(平均 ~13 帧,上限 30)中
  选出 2 帧替代 recent-2,使冻结策略做对当前步的概率更高。
- **标签(核心资产)**:对 1263 个"winnable"态,我们**枚举了全部 C(n,2)
  帧对**,每对真跑一次冻结策略前向、按步级正确率判分(动作类型匹配 +
  坐标 L2≤25,[0,999] 归一空间)。即每态有一张完整的 {帧对 → 0/1} 查找表。
  - 分层:easy(不看历史也对)/ winnable(存在能救回的帧对)/
    hopeless(任何帧对都救不回)≈ 2809 易 : 1263 可解 : ~2000 无望
    (全体 ~6000 态里被枚举的部分)。selector 只在 winnable 上产生差异。
- **为什么值得做**:winnable 态上 oracle-2(选最优帧对)比 recent-2 高
  **+28pp**;方法动机已单独验证(选对 2 帧 42.0% > 全给 8 帧 32.2%,
  且省 2/3 token)。

## 3. 已被证伪的配置(⚠️ 不要再提这些)

评测口径统一为**部署口径**:留出态上 selector 输出的帧对查表得正确性,与
recent-2 同态配对(McNemar + 态级 bootstrap),fold 划分,n=252/折,
可扩 5 折 out-of-fold n=1263。运行间噪声 ±3pp(<3pp 的差需重复种子)。

| # | 配置 | 部署口径结果 |
|---|---|---|
| 1 | 池化视觉特征(144-token 缩略图)+ 线性/MLP 打分头,加性子集分 | 代理指标即低于 recency,未进部署评测 |
| 2 | **全清 raw 特征(即 §2 的缓存)+ 单头交叉注意力打分头(dk=256),加性子集分,成对排序损失** | **−4.29pp** [−6.11,−2.46](out-of-fold n=1260);MultiApp −6.82 更差 |
| 3 | 同 2,损失换 listwise 正子集 softmax(对齐 argmax) | −3.2/−4.0/−8.7pp(三种子),不翻盘;移动率翻倍胜率不变 |
| 4 | 编码器侧 LoRA(末 8 层)让特征可学 | 代理指标未超 recency |
| 5 | 数据规模(252→1011 态)在 1/4 两族上 | 平,数据非杠杆(对小头) |
| 6 | **GUI-Owl-8B 本体全层 LoRA 生成式选帧**(输入=缩略图+B=1 逐帧动作文本+B=0 draft 文本,输出 SELECT: i,j) | **−11.5/−9.8/−8.0pp**(三种子全显著为负);移动率 75%,每动错赢 1:2 |
| 7 | 零参数规则:按"B=1 动作与 B=0 draft 不一致"排序 | +1.19pp [−0.63,+3.09] 不显著 |
| 8 | 反向规则(选与 draft 一致的帧) | −13.86pp(机制佐证:一致=无信息) |

**重要正向参照(不可部署,但证明信号存在)**:按"单帧 B=1 前向是否做对"
(用了 gold)排序取 top-2:**+11.08pp** [+8.87,+13.38],MultiApp +14.77。
即:探针**正确性**信号大;但部署时只有动作没有正确性,"判断哪个动作对"
≈ 解原任务本身 —— 这是 #6/#7 失败的机制解释。

**共同失败形态**:所有学习方法都"动得多、动则错多"(赢输比 ~1:2),
recency 在 winnable 上本身 ~50% 正确,乱动代价高。
**涌现对**:31.6% 的 winnable 态,其全部正确帧对由"单独都错"的两帧组成
—— **加性打分(帧分相加)按构造表达不了**,已试配置全是加性或
逐帧独立文本。这是最明确的未解决结构性问题。

## 4. 用户提出的方案方向(待外部细化)

- selector **不必是 GUI-Owl**:输入用 §2 的**缓存冻结视觉特征**
  (每帧 [~2584,4096],部署零成本),模型族自由 —— 例如 **Set Transformer**
  之类置换等变、**帧间可交互**(非加性)的集合模型;
- 条件信号:**pass-1 draft = recent-2 条件下冻结策略的一次前向的动作分布**
  (部署本来就要跑这一遍,免费;比 B=0 更贴部署、含分布信息);
- 输出:选 2 帧(或"维持 recent-2 / 换成 (i,j)"的门控式输出);
- 目标:直接对齐部署 argmax(注意 #3 的教训:换损失不换信息没用 ——
  但那是在无条件、加性、无 draft 信号的族里)。

## 5. 部署与验收约束

1. **允许的部署时计算**:候选帧特征查缓存(免费);recent-2 pass-1 前向
   (免费,本来要跑);selector 自身前向(轻量优先,但按用户 Pareto 打法
   "先效果后轻量",重也可)。**不允许**:逐帧 B=1 探针(13× 前向)、
   任何用到 gold 的量;
2. **训练资源**:H200 若干张,1263 态标签(每态完整帧对表 —— 监督形式
   任选:分类/排序/列表/强化,表都在);可扩标签;
3. **验收**:留出态部署口径 diff vs recent-2 **显著为正**(5 折 out-of-fold
   n=1263,CI 不跨零),MultiApp 分层单独报;超过零参数规则 +1.19 才有
   意义;oracle 上界 +28pp,B=1 正确性参照 +11.08pp 给出量级感;
4. 划分协议(必须沿用,保证与历史可比):态 id 排序 → seed 20260809
   洗牌 → 20% 折切片;评测臂与 recent-2 同态配对。

## 6. 需要外部方案回答的问题

1. 模型:集合级(候选帧数可变 2-30)、帧间交互(治涌现对)、以 draft
   动作分布为条件的架构长什么样?(特征是 token 网格 [~2584,4096]/帧,
   可池化可不池化 —— 注意 #1/#2 的教训:池化毁细节,加性毁交互);
2. 目标函数:1263 态 × 完整帧对表下,直接优化"argmax 帧对正确"的
   训练目标(并治"乱动"病:输出空间里显式包含 KEEP=recent-2?);
3. 条件注入:动作分布(结构化:动作类型 + 坐标 + top-k 备选)怎么编码
   进集合模型;
4. 数据量:1263 是否够;若要扩,优先扩态数还是每态信息;
5. 训练加测试全流程的算力/时间预估。
