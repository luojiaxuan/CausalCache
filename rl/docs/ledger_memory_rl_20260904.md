## 1. 三十秒背景

问题:冻结的 GUI executor 之上,能否**学**出一个记忆控制器(每步从历史截图里选 B 张喂给
executor),使第三方记忆 benchmark(MemGUI-Bench,128 题闭环,LLM 判分)显著提升、常规 benchmark
(MobileWorld / AndroidWorld)不退化。成功 = MemGUI Pass@1 显著高于同一 executor 的默认历史窗,
且方法是学出来的(RL 或密集反馈的 bandit),不是手写规则。

### 2026-09-04 11:10 PT ★ 用户定案:先做 Stage I,控制对象改为动态 B(设计与发射)
- 用户裁定(原话要点):(1)『先做这个吧』——指 Stage I(executor 反馈的反事实密集回报),J7 撤销;
  (2)否决我提的『文本与帧的预算分配』:记忆方向文章已拥挤,且探针本身说明『保留文本历史就够,不需要图』,
  分配问题不成立;(3)**把现在的固定 B 变成动态 B:文本部分不变,平时 B=0,需要图片记忆时才存 B 张。**
- 我的评估:用户的框架优于我的。数据直接支持它——保留文本历史时 **72% 的状态在全部 23 个上下文下输出
  同一个动作**(那些步 B=0 是免费的),B=0 已有 90.4%,而 ∃正确对 97.7%:**门控的可得区间就是这 +7.3pp,
  且大部分步不该花图像预算**。与拥挤赛道的区分点也更清晰:主流做法是**模型内部**的上下文折叠/摘要或
  **常开**检索,我们是**外挂、学出来、带预算意识的门控**,默认零成本。

**Stage I 设计(动态 B,预注册)**
- 动作空间:M ∈ {∅} ∪ {单帧 i}(6)∪ {帧对 (i,j)}(15),即 B ∈ {0,1,2};**文本推理历史恒定保留**(部署条件)。
- 回报:`r(M) = Match(E(x,M), a*) − Match(E(x,∅), a*) − λ·|M|`。以 **B=0 为反事实基线**,直接对齐门控语义;
  λ = 图像预算价格,做 sweep 出 Pareto 曲线(超参 ablation 规则)。
- 优化:RLOO(组 = 同状态多次采样 M);对照臂:恒 B=0 / 恒 recency-2 / 同预算随机门控 / 同预算监督模仿。
- **关键性质:标签集穷举全部 22 个动作,任何策略都能在其上离线精确评估**——λ sweep、对照、Pareto 曲线
  全部零 GPU 成本,只有特征抽取与训练需要 GPU。
- 闸门(预注册):在**未见模板**上,学出的门控须在平均图像预算 ≤ recency-2 的一半时,步级正确率 ≥ recency-2,
  且显著高于同预算随机门控;否则不进 Stage II。
- 数据:Venus 自身成功轨迹 204 条 → 1,726 个状态 × 23 上下文,hyper00 GPU1(41041)+ GPU3(41042)
  双服务并行标注,约 4 小时;脚本 `stage1_label.sh`,产物 `rl_v2/venus/stage1_labels_{a,b}.jsonl`。
- 已知偏置(写入 limitation,Stage II 覆盖):参考动作取自轨迹自身(自一致性偏置);仅用成功轨迹(幸存者偏置)。
