# 路 B-pilot 设计:构造"必须回看截图"的反事实孪生场景,测记忆余量(2026-09-05 22:40 PT 草案)

定位(用户 09-05 拍板):我们测的是**视觉记忆余量**及其协议/模型/训练依赖,并指出**视觉历史不该默认取最近帧**;
不做记忆控制器方法(区别于 MementoGUI)。任务集只是测余量的载体。设计约束全部来自外审
(`reviews/memory_critical_tasks_review_20260906.md`)。

## 0. 为什么要构造:自然轨迹里没有靶子

`find_memory_states.py` 在 337 个自一致状态里只找到 **1 个**"下一步要输入的内容只在更早某屏出现、且不在任务指令里"的状态。
MobileWorld 自然任务几乎不需要视觉记忆,所以余量问题必须在构造场景上问。

## 1. MobileWorld 提供的杠杆(已核实代码)

- `BaseTask.__init__(params)`:任务可参数化 → **反事实孪生**即同一任务类、不同 `params`(不同随机事实、不同正确答案)。
- `initialize_task_hook`:向设备/应用**种数据**(推文件、写邮件、建消息、改后端记录),无需改截图。
- `is_successful`:通过后端助手精确判定(`get_sent_email_info` 等:收件人、正文数字、文件位置、数据库状态),**不用 judge**。
- `run_task(agent_question)` / `initialize_user_agent_hook`:原生的 **ask-user 通道**,可用来实现外审的"延后揭示信息需求"
  (agent 先浏览若干记录,之后用户回复才指定要哪条记录的哪个属性)。
- 现有 117 任务的应用面:Mastodon(38)、Mattermost(15)、Check/Invoice/Files(约 20)、Mail/SMS/Calendar、Photos、Maps、Chrome。

## 2. 三个任务族(各 ≥3 个工作流、≥2 种渲染)

| 族 | 所需操作 | 载体(应用) | 孪生变量 | 判定 |
|---|---|---|---|---|
| A 延后绑定查找 | 浏览多条记录后,用户**延后**指定要哪条的哪个属性,agent 需回忆并输入 | Mattermost 多条报价消息 / Mail 多封邮件 / Files 多份 PDF | 记录内容(金额、日期、编号)随机;哪条被点名延后揭示 | 发出的邮件/消息正文含正确值 |
| B 两帧关系连接 | 订单→供应商在一屏,供应商→地址在另一屏,需两帧组合 | Mastodon Mall 订单页 + Mattermost 供应商目录 | 映射随机化 | 填入的地址与订单对应供应商一致 |
| C 视觉/版本绑定 | 匹配此前见过的商品缩略图 / 文档版式,或区分相关历史版本与醒目的新干扰项 | Photos + Mastodon 发图 / Mall 商品列表(位置随机) | 目标图与干扰图随机分配 | 选中/发送的正是目标 |

每族的"证据帧"由构造决定(哪一屏出现了事实),**标注全部有效证据集**(多屏含同一事实时都算),不是任意一对。
中间操作必须属于合理工作流,**独立变化**步数、中间信息量、证据年龄;不用无关点击填充。

## 3. 泄漏与"人为设限"的处理(按外审)

- 不禁止写笔记、不禁用"返回":agent 把事实写进文本轨迹是**成功的记忆**,不是泄漏。
- 真正要审的泄漏:以未来截图为条件的 teacher 轨迹、带答案生成的摘要、暴露随机值的任务元数据/文件名/工具输出。前缀轨迹因果生成。
- 延后揭示(族 A)对所有写记忆的组件不可见。
- 若要对比"文本记忆 vs 视觉记忆",用**显式资源预算扫描**(上下文/工作记忆预算),对照学习型摘要、键值笔记、OCR/文本索引;
  **全管道计费**(选择器扫全历史的成本要算)。pilot 阶段不做这一项。

## 4. 评测协议

**主评测 = checkpoint 续跑**:从第一个真正依赖记忆事实的动作前启动,给定前缀(截图 + 文本轨迹),比较各上下文下的动作
及短续跑后的本地状态。**闭环执行**只作次评测(现有成功地板 ≈0,整任务成功率分不出机制)。

每个 checkpoint 的上下文条件(图数匹配,当前屏不变):

| 条件 | 说明 |
|---|---|
| none | 不给历史图 |
| recency-2 | 官方默认 |
| source | 已验证证据帧(构造给出) |
| irrelevant | 匹配的无关帧(别的场景) |
| judge | 三裁判从全历史选(与 §2.3 同法,作可达性参照) |
| gold-text | 在决策点直接给出事实(阳性对照) |
| redacted-text | 从文本轨迹抹掉事实(只在诊断分析里用,不算部署条件) |

**核心行为指标**:反事实孪生下,**只改历史证据,动作是否变成对应的新正确答案**(比"均值不变"强得多)。
主终点:`H_source − H_irrelevant`(源帧相对无关帧的净价值)与 `V(source) − V(recency)`;逐状态 rescue/harm 同报。

模型:冻结 GUI-Owl-1.5-8B、冻结 UI-Venus-2-9B;若 source 显著 > irrelevant 且 > recency,再加:反事实 SFT 的 actor、
**无历史 SFT 对照**(区分记忆特定效应与通用微调)、按布局训练的三臂做交叉评测。**不直接联合 RL**:先 contextual bandit
+ 用金证据集的监督选择器基线。

## 5. 样本量与判据

- pilot:**24–40 个基础场景 × 2 孪生**,跨三族、≥6 个工作流;go/no-go 判据(预注册):
  ① 冻结模型上 `V(source) − V(irrelevant)` 的配对 95% CI 下界 > 0(至少一个底座);
  ② 孪生一致性:改证据后动作跟随新答案的比例 > 50%;
  ③ `V(source) > V(recency)` 在至少一族成立。三条都不满足 ⇒ 视觉通道在构造任务上也关着,写成边界清楚的负结果。
- 主研究(pilot 通过后):300–400 基础实例 / ≥12 留出工作流模板 / 3 SFT 种子 / 第二底座;按任务/轨迹 bootstrap;
  预注册一个主交互与实用等价边际。参照外审功效表:5pp 差异需 628–1,256 对。

## 6. 工程路径

1. 读 STAMP(2605.29324)与 MementoGUI(2605.18652)的任务构造与评测细节,避免重复其任务形态;
2. 各族先各写 1 个任务类(参数化 + 精确判定器),用现有 12 台模拟器跑通 checkpoint 续跑管线;
3. 前缀轨迹用冻结底座自然生成(因果),人工核对每个场景的证据帧集合;
4. 跑 pilot 条件表(约 40 场景 × 2 孪生 × 7 条件 × 2 模型 ≈ 1,100 次解码,GPU 1 张 1–2 小时);
5. 按 go/no-go 判据决定是否进主研究。
