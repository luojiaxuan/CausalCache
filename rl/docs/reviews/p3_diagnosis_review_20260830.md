## 发审前我方预判(先行锁定,防背书)

**诊断修正(用户质疑引出)**:我先前称"executor 读不懂非连续历史
(bootstrap 死结)",用户质疑"executor 也在联合训练,为何读不懂"。
数据复核后**我方收回该论断**:
- 原始相关看似极强(贴近 recency 87.0% vs 重度跳跃 34.0%),但存在
  **episode 长度混杂**——失败 episode 跑满 50 步(中位 49 vs 成功 25),
  历史越长选帧跳跃度自然越大;
- 控制 episode 长度后(短 episode 内配对)只剩 **72% vs 62% ≈ 10pp**;
  成功/失败 episode 的平均 gap 仅 7.37 vs 9.11(近乎无差),而步数差近一倍;
- 最干净证据反向支持用户:批 100 终判 heldout-39 上
  E_t×S_t 35.3% > E_t×recency 26.5%,**executor 确已适应 selector 分布**;
  先前引用的"recency 更优"来自批 60 train 域(45% vs 40%),heldout 方向相反。

**因此三项改动(我方判断)**:
1. **压制零信号任务采样**:24/75 任务 533 次尝试全 0 分、80% 跑满步数,
   吃掉约 20% 采样预算且梯度恒零;压其权重≈回收 20% 有效批大小。
2. **修 selector off-policy**:clip_frac 常年 0.55(一半样本梯度被裁),
   根因是 trainer 每 120s 消费的决策来自过去数分钟多个策略版本。
3. **放弃/降级 random-S SFT**:它教的是"读非连续历史",而诊断修正后
   该能力并非瓶颈;继续做等于教已会的东西。

**背景数据**:P2 91 批 + P3 42 批 = 133 批;批均 rate 平台化
(P2 末40批 0.431 vs P3 前40批 0.414);混合组率 57%;
selector recency_mass 0.29-0.65 震荡未收敛。

## 文献核实结果(替代性外审)

### 判断 1「压制零信号任务采样」——**文献强支持,且我方低估了普遍性**

该现象在 RLVR/GRPO 文献里有专名:**zero-variance prompt (ZVP)**——组内
所有 rollout 同分 → 组内方差为零 → 优势为零 → 无有效梯度,纯烧算力。
关键校准:文献报告标准 GRPO 随机采样下,**训练后期只有约 10% 的样本在
提供有用学习信号**;我方实测 24/75 任务(约 20% 采样预算)恒零,属于
同一现象的温和版本,方向判断正确但**严重性可能被我低估**。

现成解法三类,可直接借鉴:
- **过滤式**:DAPO 的 Dynamic Sampling——检测零方差组并重采样;缺点是
  先全量 rollout 再事后丢弃,开销大(与我方"预算已花掉"的痛点同源);
- **信号级**:RL-ZVP——即使奖励零方差,也用 per-token 策略熵构造非零
  优势(不丢样本);
- **采样级**:VADE——在线估计样本难度,**rollout 之前**就避开梯度消失。
  我方"压制零信号任务采样权重"属于此类,是三者中开销最低的。

### 判断 2「修 selector off-policy」——**文献强支持,且给出了精确机制**

我方观察:clip_frac 常年 0.55,决策日志来自过去数分钟的多个策略版本。
文献对应表述:陈旧 rollout 使 **importance ratio 重尾**,少数轨迹主导
更新,PG 估计量高方差;更精确的一条——**同一个 importance ratio 需要
同时承载"rollout 陈旧度"与"梯度更新期间的策略变化"两种偏差,裁剪这个
耦合比率会混淆两者,导致过度裁剪事件**。这正是我方 55% 裁剪率的机制
解释,比我原先"数据陈旧"的粗描述精确。

另有两个可借鉴点:
- **M2PO**(二阶矩信任域代理):在高陈旧度下显著降低被裁剪 token 比例,
  同时保持稳定;
- **"prosperity before collapse"**:无信任域训练呈"先改善后崩溃"两段式,
  以及 staleness × learning-rate 是控制稳定性的**主要杠杆**——这提示
  我方若缩短消费周期(降 staleness),lr 或可同步上调。

### 判断 3「放弃/降级 random-S SFT」——**文献部分支持,但给出一条反向提醒**

支持面:GUI agent 领域已整体从 SFT 转向 RL(GUI-R1 用远少于 SFT 的数据
达到 SOTA);SFT 的已知缺陷正是**协变量偏移**——agent 遇到训练分布外的
状态时缺乏恢复机制,误差累积,而动态 GUI 里这种偏离是常态。这与我方
"executor 已在联合训练中适应了 selector 分布"的实测一致。

反向提醒(我方需正视):文献明确指出**稀疏轨迹级奖励对长视界 GUI 任务
"不足以"**,30+ 步工作流常在学到成功策略之前就优化失败。这与我方 24 个
恒零任务(80% 跑满 50 步)完全吻合——**那 24 个任务不是"多训能解决"的,
文献给的解法是奖励塑形/过程奖励/MCTS 分解 credit,或从失败集生成简化
任务(WebRL 式课程),而不是继续同配方训练**。

## ★ 极高档外审(2026-08-30 重做,思考 2m2s + 检索 7 站)

> **重做原因(用户指出)**:上一轮我用了"极速"(最低)档,只是快速意见,
> 不配叫外审。skill 已补硬规则:发送前必须确认档位并切到次高档以上,
> 回复无"思考了 Xm Ys"字样即作废重发。本轮档位 = 极高(Pro 之下最高)。

**开场判决**:"我会**把 random-S SFT 移出主线、保留 learned-selector 假设
不杀、且暂时不要缩短 120s 窗口**。先确定 0.55 的裁剪率到底是陈旧、
优化器过猛,还是 PL 记账 bug。"

### (a) 审稿人会攻击的三点

1. **你还没有任何令人信服的证据表明"selector 学习"导致了什么**。
   34 题上 35.3% vs 26.5% 就是 **12 胜 vs 9 胜,差三个任务**,p=0.45 只能
   算暗示。更要命的是 executor 与 selector **协同适应**,所以最终的
   learned-selector 对比**无法干净地识别 selector 学习**。审稿人完全可以
   说:"也许是 executor 变强了,selector 只是搭便车。"
   **它要的实验**:**冻结 executor 的 selector-only 评测**,每个未见任务
   多次随机 rollout,在**完全相同的 executor checkpoint** 下比较
   learned / initial / recency。
2. (第二点被滚动截断,要点为"零信号任务的处理不能变成忽略难任务")
3. **一个我方主动要防的第四问题**:**不要说"控制长度后的结果证伪了
   非连续历史假设"**。最终 episode 长度**受成功与 selector 行为双重影响,
   是 post-treatment 变量**;对它做条件会引入 collider bias。**正确的
   匹配单位是"任务 × 决策步 / 历史长度"**,或者在保持决策状态固定的前提下
   直接对帧做干预。

### (b) 放弃 random-S SFT:**结论对,但理由不能用 p=0.45**

"**从主线移除:对。但别据此断定 SFT / 历史鲁棒性没用。**"
原因链条:你原来的动机是"非连续帧 → executor 失败 → 用随机子集训 executor";
**这个因果前提已不成立,所以大规模 random-S SFT 现在是无动机的干预**——
这就足以移出主线。**但 n=34、p=0.45 不是"无 selector 效应"的证据**:
你拿到的是 **8.8 个百分点的数值提升**,只是功效不足。
替代方案(与低档那轮一致但更具体):**一个便宜的诊断**——取**固定的已记录
决策状态**,只扰动 S(learned / initial / recency / 按帧龄匹配的随机),
其余全部保持不变。

### (c) 24 个零成功任务:**先分诊,再制造第一条成功轨迹**

给了混合组概率公式,**这是最有价值的量化工具**:
> P(mixed group) = 1 − p⁸ − (1−p)⁸

读法:p=0.5 时几乎每组都有信息;**p=0.01 时只有约 7.7% 的组会出现混合
结果**。这精确解释了为什么近零和近一成功率的任务是 group-RL 预算的
劣质用法。

**"对这 24 题,我不指望稀疏终局 RL 能神奇地解决它们。它们需要的是
数据分布的改变。"** 它的顺序:
1. **先人工分诊一次**:把每个失败标注为 环境/评测器问题、能力缺失、
   动作或感知错误、探索失败、视界/循环。**注意 MobileWorld 官方平均
   需要 27.8 步、评测上限 50 步,所以撞上限有意义,但撞上限本身不证明
   上限是根因**。
2. **给每个"有效"任务弄到至少一条成功轨迹**(更强的教师、脚本轨迹、
   人类轨迹、搜索——任何训练上可接受的手段),然后 SFT / 行为克隆
   这些轨迹**或其关键后缀**。
3. **若环境支持快照,用 reverse curriculum**:从"距成功 5-10 个动作"的
   状态开始,再逐步把重置点前移。**对稀疏 GUI 任务,这比再来几百次
   端到端零奖励尝试更可能跨过探索壁垒。**
4. (截断)
5. 每批保留约**一个任务组**作为 hard/bootstrap 池的探针。

### (d) PL slate policy 的 0.55 裁剪率:**六因 × 各自签名**

| 可能病因 | 你会观察到什么 |
|---|---|
| 1. 行为策略陈旧 / 版本偏移 | 裁剪率随"采集与学习之间的 selector 更新次数"**单调上升** |
| 2. 单次 selector 更新步子过大 | **即使 age=0 的新鲜数据**,一两个优化步后就从 ratio≈1 变成重裁剪 |
| 3. PL logprob 记账 bug | **用精确的行为 checkpoint 重算时 ratio ≠ 1**(在任何优化之前) |
| 4. 联合比率乘法放大了温和的单抽变化 | 每个 slot 的比率看着都还好,但**它们的乘积频繁越界** |
| 5. 稀疏终局 credit 造成参数震荡 | 梯度范数/震荡集中在混合奖励组;策略统计大幅摆动却无稳定偏好 |
| 6. 分布过尖 / 候选集增长 / 数值问题 | 裁剪强烈依赖历史长度、PL 熵,或极低概率被选项 |

**关键的 PL 细节是 #4**。对有序两帧抽取:
> log r_joint = Δ log p₁ + Δ log p₂

你的 0.2 裁剪意味着**联合比率一出 [0.8, 1.2] 就被裁**。**如果两个 slot
的概率同向移动,每个只要动 ±9.5% 就足以让联合比率越界**。

**三步诊断(它给的执行顺序)**:
- **第一:重放自检**。用**精确的行为 checkpoint** 重算 logprob,
  **优化前 ratio 必须严格等于 1**。若不等于 1,就是实现 bug,先修。
  它列了具体的 bug 面:抽样时是有序对 (i,j) 但存储/排序成了 (j,i) 或
  时间序;旧概率算的是**有序序列**而新概率算成**无序对**;第二抽是否
  正确 mask 掉第一抽;候选帧是否按**日志里那个时间步**重建而非当前历史;
  温度不匹配;padding/去重/frame-ID 不匹配。
  "**有序 vs 无序这个问题我会非常早就去查。**"
- **第二:用策略版本而非秒来度量年龄**。记录 `behavior_version`、
  `learner_version`,从而得到 `Δupdates`;画 clip fraction、
  |Δlogp| 的中位数/95 分位、以及 KL 对 `Δupdates` 的曲线。
  "**120 秒的桶是个弱代理,因为更新吞吐会变。**"
  判据:**若 age0 是 5%、+2 更新是 25%、+8 是 60%,那就是策略滞后**,
  该缩窗口/更频繁同步/拒收过龄样本;**若非常新鲜的样本就已经 50%,
  那么缩短 120s 基本没用。**
- **第三:冻结一个新鲜批,逐步追踪**。优化步 0 之前 ratio 必须等于 1,
  然后记录第 1、2、3 步后的变化——**若一步之后就从 0 跳到 40%,
  那 3e-4 对这个头就是过猛**。
- **报告口径修正**:要同时报 **raw out-of-band fraction** 与
  **loss-active clip fraction**,并按 RLOO 优势的正/负/零分区——
  "**否则 0.55 听起来会比实际的优化影响更糟。**"

### 它建议的下一步:**下一轮跑仪表化,而不是新干预**

> "**保持 selector 的 lr 与窗口不变,先跑一轮诊断。** 加上精确的策略
> 版本号、行为 checkpoint 重放、per-slot PL 比率、候选数/熵、优势符号、
> 梯度范数,以及 clip fraction 对版本年龄的曲线。"

**决策树**:
- 重放 ratio ≠ 1 → **修实现**;
- 重放没问题 + 年龄斜率陡 → **减少滞后 / 按年龄过滤数据**;
- 新鲜样本一步后就裁剪 → **降 lr / 归一化梯度 / 减少更新次数**;
- 单 slot 正常但联合糟糕 → **重新考虑联合裁剪阈值或目标函数**;
- 以上都正常但策略仍震荡 → **是 credit assignment 问题,不是陈旧问题**。

> "**我不会同时改 120s 和 lr。那样你就失去了搞清自己到底是哪种失效模式
> 的机会。**"

**它认为我方数据今天能支持的高层故事**:

> "**executor 的学习在稀疏终局奖励下已经饱和;大约三分之一的任务处在
> 当前探索前沿之外;selector 学习可能有帮助但统计上未获证明,而它的
> 优化器目前可疑,因为联合比率裁剪很重。** 这是个站得住的故事。
> '非连续历史是瓶颈' 不是。"

## 我方裁决(极高档外审后定稿)

**它同意的**:三项方向成立;random-S SFT 移出主线正确;零信号任务确实
是 group-RL 预算的劣质用法。不展开。

**它反对、我方改判的(4 条,全部采纳)**:

2. **"按秒分桶"是弱代理,应按策略版本计龄**。记录 `behavior_version` /

   单位是**任务 × 决策步/历史长度**,或在决策状态固定下直接干预帧。
   **这条修正了我给用户的上一版分析的方法学缺陷**,必须如实告知。

**它给的、我方此前没有的量化工具**:

- **混合组概率 P(mixed) = 1 − p⁸ − (1−p)⁸**。p=0.5 时几乎每组有信息;

- **报告口径**:要分别报 raw out-of-band fraction 与 loss-active clip

**分歧(我方保留)**:无实质分歧。它对 24 题的处方(教师轨迹 / 脚本 /
人类轨迹 / reverse curriculum)全部越出当前 frozen contract,属于需要
用户拍板的方向性决策,我方记录但不擅自启动。

## 执行顺序(极高档外审后定稿,替代前一版)

**第 0 步(必须最先,零算力):`slate_logprob` 重放自检。**
用记录时的行为 checkpoint 重算已落盘决策的 logprob,断言优化前
`|ratio − 1| < 1e-5`。重点查有序/无序配对、第二抽是否正确 mask 第一抽、
候选帧是否按日志时间步重建、温度一致性。**若不等于 1,先修 bug——
后面所有诊断都建立在这个前提上。**

**第 1 步:仪表化(lr 与窗口不动)。** 加 `behavior_version` /
`learner_version` / `Δupdates`;per-slot PL 比率与联合比率分开记;
候选数与熵;优势符号分区;梯度范数;raw vs loss-active clip 两种口径。
跑一轮,画 clip_frac 对 Δupdates 的曲线。

**第 2 步:按决策树处置**(重放≠1 → 修实现;年龄斜率陡 → 减滞后;
新鲜样本一步即裁 → 降 lr;单 slot 正常而联合糟 → 改联合裁剪阈值/目标;
全正常仍震荡 → credit assignment 问题)。

**第 3 步:采样重加权**,用 P(mixed) 公式定权重(而非拍脑袋的"极小
floor"),三层分配保留前沿与审计配额。

**第 4 步:冻结 executor 的 selector-only 评测**(多次随机 rollout、
同一 executor checkpoint、按任务×决策步匹配),给 selector 效应一个
有功效的估计;这同时替代我方那个有 collider bias 的长度控制分析。
