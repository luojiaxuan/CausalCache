# 外审:路 B(构造记忆关键任务)该不该直接做(GPT-6 Pro,2026-09-05 21:40 PT)

起因:三臂配对 SFT + 三裁判 + seed 复现 + 未见闭环全部落地后,结论收窄为"文本轨迹即记忆通道;截图无额外可用信息"。
用户拍板先 C(Venus 跨模型)后 B(构造"必须回看截图"的任务)。按纪律,B 投入实现前发审。

## 1. 审前判断(先写后审)

- 主张:训练后 V(真实历史)≈V(无关历史)≈V(不给图) ⇒ 模型只是对图不敏感;三裁判 54 格压零 ⇒ 截图无额外信息;
  由此推断"文本轨迹已含所需记忆",并解释两次联合 RL 零梯度。
- 计划:在 MobileWorld 内构造"数据只在第 k 屏出现一次、k+10~20 步必须用、文本轨迹不可恢复"的任务变体,
  oracle 帧由构造给出,回报对选帧敏感,SFT→RL,检验"冻结排名 ≠ 训练后排名"。

## 2. 外审要点(按原文段落转录,英文原句意译)

**开场判决**:"The plan is worthwhile as a causal stress test. It is not yet a justified next training run, and it does not
automatically test 'frozen ranking differs from trained ranking'." 三个问题要分开:所需信息是否缺失;actor 能否用上它;
训练是否改变最优检索策略。我的构造只回答第一个,部分回答第二个,几乎不回答第三个。

**新颖性警告**:**STAMP(2026-05-28)**已经在 GUI 任务里程序化注入瞬态记忆变量、控制其出现与复用时机,并用这些环境做
SFT 与 online RL,底座正是 GUI-Owl-1.5-8B-Think。它强调的是显式文本记忆而非截图选择策略的因果比较,但"构造记忆关键
GUI 任务 + SFT–RL"已是被占的地盘。可区分的贡献必须是**因果的、多模态的、序列 agent 上的 reader–retriever 交互结果**。
另:MemGUI-Bench 已含跨长交互的事实保持任务;AGMem 已报告全图记忆可减少某些错误同时加重另一些;RA-DIT 早有
reader 与 retriever 分别适配的先例。

**"我的诊断强于证据"**:
- 可辩护的结论只是:在这些状态、现有文本上下文与接口下,受测截图策略的边际效用很小或为负;SFT 大幅减轻了历史截图的惩罚。
  **这不等于证明文本轨迹含全部所需记忆。** V(真实)≈V(无关)≈V(不给) 可能是忽略历史图,也可能是有益与有害效应相抵、
  视觉读取差、当前/过去混淆、或成功回忆之后的下游失败。要看**逐状态的动作变化与救回/伤害计数**,不只看聚合均值;
  同时报 H 背后的绝对值(差分变小可能来自历史条件变好、无历史条件变差、或两者)。
- **三个裁判不是三个经验证的 oracle**:架构多样只防单个裁判的怪癖,不能验证它们共享的"信息量"概念、不能证明两帧够用、
  不能证明这个 actor 能提取并使用其内容。**54 格共享同一批状态与模型,不是 54 次独立复现**;"点估计在 ±8pp 内"不是
  实用等价的证据。
- "不给图会错"的子集适合做救回分析,不足以支撑机制主张:这些状态可能因与记忆无关的原因失败。**最适合证明文本替代的
  反而是"不给图也对"的状态**——把文本里的关键事实抹掉,看截图能否恢复。
- **闭环地板是大混杂**:1/40、0/42、0/41 分不出检索机制;0/42 的精确 95% 区间上限仍达 8.4%。要审计为什么 44 个任务
  出了三个不同分母,用跨方法固定的规则区分环境无效与 agent 失败。
- 文本记忆假说本身合理:GUI-Owl 文档化的上下文机制保留近期多模态 turn、把更早的 turn 压缩成文本动作结论,训练管线明确
  包含"记录屏幕信息(含价格)供后用"。这支持假说,但**不能替代在我们自己的 harness 里对文本通道做干预**。
  两次联合 RL 的零结果与回报不敏感一致,但**尚未定位原因**:"事实已在文本里"与"actor 用不了正确截图"指向完全不同的下一步。

**(a) 计划的循环、平凡与薄弱处**:
- 围绕随机化事实构造任务本身不循环。循环出现在隐含论证"我们构造了必须选指定帧的任务 ⇒ 选指定帧重要 ⇒ 我们的检索方法
  解决了重要问题"。构造能确定**证据在哪**,不能确定 actor 能否受益、检索问题是否非平凡、任务分布是否有代表性。
  要分开三个量:**证据覆盖**(选中的帧含所需信息吗)、**证据使用**(有了信息 actor 做对了吗)、**执行**(决策导致了
  可验证完成吗)。已知源帧只解决第一个。
- **单个隐藏标量基本是查表测试**:验证码/价格/地址是同一任务族(延迟事实查找)的三种表面形式。L 个候选里一个必需帧,
  均匀抽对包含它的概率 2/L;若证据总在 10–20 步前,recency 被**刻意剥夺**答案。"actor 学会读源帧后更广采样胜出"主要是
  证据覆盖的后果——有用的 sanity check,弱的标题结果。
- **学会用证据不必然反转排名**:U_θ(P) = b_θ + g_θ·Pr(P 覆盖所需证据),训练把 g 从≈0 变正,是把平局变成排序,
  不是在有信息的替代方案之间反转。要检验有意义的 reader 依赖排名,必须包含**各有优势的替代方案**:完整但杂乱的证据 vs
  更干净的部分证据;直接查找 vs 两帧组合;更早的正确版本 vs 视觉上更醒目的新干扰项。**不要预先设计训练后必须谁赢。**
- **填充不制造长程难度**:十几次无关点击制造距离,不必然制造记忆挑战;若 agent 能在正常轨迹里无限期保留"code=583219",
  延迟什么也不改变。用属于合理工作流的中间操作;独立变化步数、中间信息量、证据年龄。
- **可以人为制造回报敏感而不解决问题**:奖励"选中标注源帧"按定义给选择器信号,那是合法的监督或 shaping,**不是**任务回报
  依赖选帧的证据。决定性检验是:**把源帧换成匹配的非源帧,在 actor 与其它输入固定时改变了可验证的任务行为**。这项检验
  要与任何金帧奖励分开。
- 出版判断:小型合成 benchmark + 正向 SFT/RL 结果区分度弱。一项受控研究——**文本记忆何时可替代视觉历史、何时失效、
  冻结策略上的检索评测能否预测训练后策略的效用**——即使带一个边界清楚的负结果也强得多。

**(b) 防文本泄漏而不人为设限**:
- 无法既让一个不受限、称职的文本记忆系统丢掉已知的六位码,又叫这个设定"不受限"。**数据便宜可序列化,写下来是正确的解法,
  那不是泄漏而是成功的记忆。** 真正的泄漏是:以未来截图为条件的 teacher 轨迹、带最终答案生成的摘要、暴露随机值的任务
  元数据——这些要单独审计。
- 三条站得住的路:(i) **延后揭示信息需求**——agent 在正常工作流里浏览多条记录,之后才被告知需要哪条记录的哪个属性;
  该延后请求对所有写记忆的组件(含 teacher / 摘要器)不可见,前缀轨迹因果生成;这防止了以答案为条件的特权摘要,但不保证
  好的文本存储会失败——也不该保证。(ii) **显式资源预算而非定向审查**——固定的工作记忆/上下文预算若反映被研究的系统且
  一致施加则站得住;"不许写下验证码"站不住。让 agent 自己分配预算,**扫预算**而不是挑一个让图片赢的点;对照学习型文本
  摘要器、结构化键值笔记、OCR/文本索引检索;**全管道计费**(写记忆时的截图处理、选择器计算、检索读取、actor 上下文)
  ——扫全部视觉历史的选择器不因 actor 只收两张图就算"便宜的两图方法"。主张变为"在指定资源预算下,保留原始视觉证据
  保存了受测在线文本记忆丢失的有用信息"。(iii) **加入真正视觉的指代物**——匹配此前见过的商品缩略图、文档版式、附件、
  位置会变的视觉选项;不做任意视觉谜题,指代物绑定普通 GUI 任务,并带强 caption/文本记忆基线。
- 允许合法恢复:能导航回去重读源头是有可衡量成本的合法策略;不可恢复的历史用自然变化的版本或瞬态状态实现,**不要为保护
  benchmark 而任意禁用"返回"**。诊断实验里定向抹除完全可接受;把它当不受限的部署条件呈现才有问题。

**(c) 最小任务设计与样本量**:
- 三个任务族而非三种数据类型:**延后绑定的事实查找**(建立未知未来需求下的保持与检索);**两帧关系连接**(订单→供应商
  在一屏,供应商→地址在另一屏;让两帧预算实质化,测互补证据);**视觉或版本特定绑定**(匹配先前视觉指代物,或在合理的
  过期/新干扰项中区分相关历史版本;测源身份与干扰而非字符串复制)。每族多个工作流与渲染;一种固定表单里随机化价格不算
  独立任务多样性。MobileWorld 技术上合适:自托管应用有后端访问,评测支持文本匹配、数据库检查、本地存储检查、回调——
  用这些做精确结果验证,不要判"看起来成功"。
- **核心构造:反事实孪生**——每个基础场景造两个版本,记忆内容与正确答案不同,当前查询与非记忆决策上下文尽量相同
  (地址 z0 ⇒ 输入 z0;z1 ⇒ 输入 z1)。选不改变前序控制流的事实;改底层应用数据并重渲染,不打醒目的截图补丁。受控通道
  实验里固定非记忆文本;自然 agent 评测里各世界诚实生成文本——**两个估计量不要混淆**。关键行为不是"oracle 帧提升准确率",
  而是**只改任务相关的历史证据,动作就变成对应的新正确答案**。随机化证据位置、干扰项位置、答案格式、实体名;检查提示、
  文件名、工具输出、动作参数、缓存上下文、摘要里有无带答案的侧信道。**标注全部有效证据集**,不是任意一对。
- **先分离导航与记忆再合并**:两级评测——(i) **checkpoint 续跑**:从第一个真正依赖记忆事实的动作前开始,验证输入值或
  短续跑后的本地状态;(ii) 闭环执行。鉴于现有成功地板,checkpoint 续跑先做主评测,如实报为组件评测。示例:若只有 5% 的
  轨迹到达相关决策点,30 点的条件记忆改善最多带来 1.5 点整任务改善。
- **训练条件 × 评测选择器交叉**:I = [U(θ_trained,P_A) − U(θ_trained,P_B)] − [U(θ_frozen,P_A) − U(θ_frozen,P_B)];
  I>0 只表明相对效用变化,**反转还要两个 within-reader 对比可信地异号**;冻结时平局、训练后有偏好不算反转。至少对
  冻结 actor、**匹配的无历史 SFT actor**(区分记忆特定效应与通用微调)、以及均衡混合条件训练的 actor 评测同一组选择器;
  若按 recency/连续/散开分别训练,要**交叉评测**,区分"这个训练后 actor 的最优选择器"与"哪种历史采样配方产出最好 actor"。
  **SFT 样本必须让正确动作随记忆内容变化**——目标动作在布局扰动下相同虽能控制干扰变异,但单独用它允许忽略历史的解。
- 样本量:pilot 24–40 个反事实基础场景(go/no-go);主 checkpoint 研究约 300–400 个基础实例,分布在 ≥12 个留出工作流模板
  (每族 4 个,跨多个应用组合);留出工作流/渲染而非仅随机值;反事实版本与重复解码不增加独立实例数;主对比 3 个 SFT 种子;
  超出 GUI-Owl 的主张要第二个底座复现;闭环验证约 200–400 个匹配场景。配对二元终点的粗略功效公式 n ≈ 7.85·q/δ²
  (q 为两条件不一致比例):10pp 差异需 157(q=0.2)~314(q=0.4),5pp 需 628~1,256。**我们当前 J 的 ±1.9pp 半宽意味着
  在 +1.5pp 真实效应下 80% 功效约需 1,100 个状态**,任务聚类与训练种子变异还会抬高。按任务/轨迹 bootstrap;模板泛化主张
  要处理模板级依赖;12 个留出模板是窄研究的地板。**预注册一个主交互和一个实用等价边际**;36 个近零点估计远不如一个
  有功效、可解释的对比。

**(d) 更便宜的决定性实验**:缺的是**在已验证的记忆依赖决策点上对文本与视觉通道做因子干预**。
- 从现有轨迹里找 24–40 个"即将的正确动作可证依赖更早事实"的状态,**包含不给图也对的状态**;源头用人工或环境溯源确定,
  不需要另一个通用选帧裁判。
- 对冻结 actor 与一个代表性训练后 actor,做 文本条件 {原始轨迹;抹掉关键事实的轨迹} × 视觉条件 {无;匹配的无关帧;已验证
  源帧;源帧裁切},加**金文本阳性对照**(在决策点直接给出事实)与**假抹除对照**(抹掉可比的非关键文本)。数百次 actor 调用,
  不是又一轮训练。保持当前屏分辨率与位置不变;需要时匹配图数与预处理;裁切条件是诊断,不是无辅助选择器的公平替身。
- 解释树:原始文本可行、抹除有害、源帧恢复、无关帧不恢复 ⇒ 文本替代 + 潜在视觉效用的强证据;金文本可行但源帧不行 ⇒
  问题在视觉提取或视觉上下文使用而非选择(让模型单独从源帧提取事实;裁切救回可进一步定位);提取对但不用于动作 ⇒ 先训
  证据到动作的映射再训检索;金文本也救不回 ⇒ 该状态还不是检索学习目标(修接口/任务理解/grounding/评测器);抹除无影响 ⇒
  "文本携带事实"在该状态不成立,查其它信息通道与动作是否真依赖该事实。
- 然后在受控文本条件下做**源帧内的反事实取值交换**:真在用记忆的 actor 应跟随替换值——比"真实与无关图均值不变"强得多。
- **复用已有记忆任务再造生态**:MemGUI-Bench 仓库用的是 MobileWorld 的 agent 接口与共享运行时(观测/动作/轨迹/调度均
  MobileWorld 格式),借一小组经审计的记忆工作流比另起一套栈更可行(它核实了文档,未执行集成)。若仍担心裁判,可在小诊断
  子集上穷举帧/帧对估计经验上界;随机 actor 下要把候选选择与新鲜评测分开,否则最大化含噪分数得到乐观的"oracle"——那是
  上界诊断,不是可部署检索器。
- **不要直接跳到联合 RL**:源帧可靠影响 actor 动作后,先在已知充分证据下做反事实 SFT 训 actor,再冻结它、用已验证的下游
  正确性比较选择器;单次检索决策 + 短续跑起初是 contextual bandit,不需要长程联合 RL;用金证据集的监督选择器是必做基线。
  只有两个组件都有可测能力、且**任务回报**(不只是辅助的选源奖励)随选择变化时才引入联合优化。**RL 不是建立原始科学
  主张的必要条件**:一个恰当交叉的冻结 vs SFT 实验已能显示训练是否改变选择器排名。

**底线**:不直接做完整记忆关键 benchmark + 联合 RL。先建立链条:**事实被需要 → 从文本抹掉它有害 → 正确截图恢复它 →
换掉该截图改变正确动作 → 训练改变选择器的相对效用**。当前结果没有完整建立其中任何一环,但足以动机去检验。最强的
前瞻论文不是"我们终于让截图有用了",而是:**文本记忆何时让视觉检索冗余、何时失效、actor 训练如何改变检索特定证据的
价值**。若公平的文本记忆基线一直赢,那是答案,不是要消灭的 benchmark 缺陷。
