# 章节稿:历史截图为什么会伤害 GUI agent——指令之后的视觉上下文塌陷(post-instruction visual-context collapse)(2026-09-06 16:30 PT 第二稿)

本稿按 *More Thought, Less Accuracy?* 的叙事顺序组织:现象 → 错误分析 → 机制假设与干预 → 触发物 → 方法含义 → 跨模型与局限。
所有数字均来自 `ledger_harm_20260906.md`,状态集为 GUI-Owl-1.5-8B 在 MobileWorld 上的 337 个自一致状态(取自 recency-2 成功轨迹;
采样条件于成功,见台账 §"两条口径警告"),指标为步级动作复现率(温度 0 下模型是否复现自己在同一状态下的原动作),
除非注明,布局均为**部署布局**(agent 真实看到的交错多轮消息)。

## 1. 现象:历史截图先益后害,且形态是"提前终止"

| 历史图数 N | 真实最近 N 帧 | 同数量无关任务帧 |
|---|---|---|
| 0 | 71.8 | — |
| 1 | 87.8 | 81.3 |
| 2 | **93.5** | 84.6 |
| 3 | 90.2 | — |
| 4 | **70.0** | 68.2 |
| 6 | 72.4 | — |

- N=1–3 把复现率从 71.8 抬到 93.5;N≥4 骤降到 70。
- 骤降的错误里 73–74% 是输出 "Terminate, task finished",而目标动作无一是终止(N≤3 时终止为 0)。
- 结构与内容两部分价值:无关帧也比无图高 13 个点(84.6 vs 71.8),真实帧再高 9 个点(93.5 vs 84.6)。
- 官方榜单协议是 N=0(history_n=1),recency-2 是本项目的约定;GUI-Owl 原生协议的短窗口恰好落在这条曲线的顶点。

## 2. 错误分析:伤害的形态与图的内容无关

在标注器布局(图连排在前 + 全部 conclusion)下把"不给图对、给图错"的状态分类(`harm_error_classes.py`):

| 条件 | 早停 | 类型漂移 | 过期动作复读 | 坐标漂移 |
|---|---|---|---|---|
| recency-2 | 0 | 15.6 | 40.6 | 37.5 |
| 无关帧 | 0 | 15.9 | 30.4 | 49.3 |
| 裁判选帧 | 0–1.7 | 10–12 | 24–35 | 52–61 |

三种给图条件下占比接近:**伤害的形态不取决于图里有什么**。无关任务的图同样诱发"复读自己更早的动作",说明"多了图"本身
削弱了对当前屏的锚定。这一发现把后续机制搜索从"内容混淆"转向"呈现结构"。

## 3. 机制假设与干预

候选假设与裁决:

| 假说 | 检验 | 结果 |
|---|---|---|
| H1 视觉稀释(当前屏注意力被历史图摊薄) | HF eager 前向、40 态、逐轮拆注意力 | 当前屏注意力 10.0 → 7.9%,与 23 点的骤降不成比例 → **排除为主因** |
| H2 时序歧义(分不清哪张是当前) | 标注器布局:历史帧加 PAST/CURRENT 标记,或换成同 token 的灰图 | 伤害完全消失(55–59 → 63.5–64.4)→ **支持**(机制 B,只在无轮次结构时出现) |
| H3 token 数 | 灰图对照 | 灰图与真实帧 token 相同却无伤害 → **排除** |
| H5 长交错历史诱发终止 | N=4/6 的错误 73% 是终止 | **支持**(机制 A) |
| H5′ 目标稀释(指令注意力被推远) | 指令注意力 26.5 → 8.1%;把指令重复到当前帧旁边 | 重复无效(70.0 → 71.8,CI 含 0)→ **降为相关** |

针对机制 A 的直接干预全部无效或更差:

| N=4 的干预 | 复现率 | 错误中 terminate |
|---|---|---|
| 原样 | 70.0 | 73% |
| 首条消息加"任务未完成勿终止" | 68.8 | 73% |
| 指令重复到当前帧旁边 | 71.8 | 56%(省下的终止变成别的错) |
| 回复只留 conclusion 一行 | 55.8 | 48%(复现线索一起丢) |
| 回复置空 | 51.7 | 10% |

## 4. 触发物:指令之后、最近两轮之前的图块数,阈值为 3,与内容无关

把所有部署布局的解码按"轮数 / 图数 / 放法"排在一起(`turns_vs_images.py`),并补做四组分辨实验:

| 条件 | 带原文回复的轮数 | 图数 | 复现率 | 总终止率 |
|---|---|---|---|---|
| rec3 | 3 | 4 | 90.2 | 0.0 |
| rec4 | 4 | 5 | 70.0 | 22.0 |
| 2 张标记老帧塞进指令消息(hybrid-first) | 2 | 5 | 73.0 | 19.9 |
| 2 张标记老帧放当前帧旁边(hybridlast) | 2 | 5 | 83.7 | 0.7 |
| 2 个参考轮插在指令**之前**(hybridturn) | 2 | 5 | 88.3 | 0.7 |
| 同样的参考轮插在指令**之后**(hybridturnin) | 2 | 5 | 73.6 | 20.5 |
| 参考轮换成**灰图**,插在指令之后 | 2 | 5 | 73.0 | 19.9 |
| 参考轮换成**纯文本**,插在指令之后 | 2 | 3 | 93.8 | 0.0 |
| rec4,早期回复换 "Noted" | 4 | 5 | 76.6 | 16.6 |
| rec6,早期回复换 "Noted" | 6 | 7 | 80.4 | 11.9 |

四个结论:
1. **轮数和图数都预测不了终止**:同为 5 张图,终止率从 0.7% 到 22%;同为 2 轮,从 0.7% 到 20%。
2. **位置是必要条件**:同样两张老帧、同样的中性回复,放在指令之前 0.7%,放在指令之后 20.5%;放在当前帧旁边 0.7%。
3. **与内容无关**:灰图与真实老帧塌得一样(19.9 vs 20.5%)。
4. **是图不是文本**:纯文本参考轮插在同一位置不但不塌,复现率与 rec2 持平(93.8 vs 93.5);把动作回复换成中性句只回收 5–8 点。

因此机制 A 的表述收窄为:**GUI-Owl 在"任务指令 + 若干个图块"之后倾向输出终止;这是一个位置化的、内容无关的图块计数效应**
(外审建议的命名:post-instruction visual-context collapse,归入多图 VLM 的 position bias 家族,与 V2PE 的"视觉位置外推"论点相容;因果归因暂不写 "caused by OOD")。 剂量曲线(`fig2_trigger.png`)是**阶跃**:指令之后 1 张灰图无事(92.6 / 终止 0%),2 张就塌(72.4 / 20.8%),3–4 张不再加深(21.4 / 16.3%);
等 token 的纯文本 2 块无终止(88.7),4 块(≈4 张截图的 token)只有 7.7% 终止、复现 81.3。合上 rec3 不塌 / rec4 塌,规则是:
**从指令消息数起、到最近两轮之前,图块数 ≥3 就塌**——一个离散的格式边界,而不是随长度渐变的退化;文本长度只贡献一个小的渐变距离效应。

它与注意力探针一致:被推远的是指令(26.5 → 8.1%),当前屏几乎不变——但补回指令无效,说明模型不是"忘了任务",而是在
"指令 + 一串图"之后按训练分布补全出"收尾"。GUI-Owl 官方协议只给 1 轮历史(history_n=1),它见过的输入形态是"指令 + 至多一两张图";
指令之后的图越多,越是分布外。

## 5. 方法含义:视觉历史不该默认取最近图,也不该多保留轮

1. **检索到的老帧放在指令之前作为参考轮**(hybridturn):不触发终止,复现率 87–88%,只比 recency-2 低 5 个点,
   比"多保留轮"(pick,约 70%)高约 18 个点。这是"视觉历史不该默认取最近图"在 GUI-Owl 上可落地的呈现方式。
2. **文本形式的历史可以任意长**:官方协议把历史折叠成 conclusion 列表,正好踩在安全区里。
3. 给 GUI-Owl 更多最近帧(N≥4)是纯粹的伤害,与记忆容量无关;比较不同记忆策略时必须先把这条病理曲线校准掉,
   否则"多帧无益"会被误读为"视觉记忆无用"。

## 6. 跨模型:这是 GUI-Owl 的病理,不是 GUI agent 的通病

UI-Venus-2-9B(原生多轮协议,400 态,保留文本轨迹):N=0→1 复现率 88.7→91.6 后饱和,N=8 仍 91.6;无关帧 84–87;
错误里 Finished 占比 3–7% 且与 N 无关。真实历史帧对 Venus 一直比无关帧值 4–7 个点;去掉文本轨迹后,裁判选的老帧比无关帧多救回
+20~+31pp。视觉历史该取多少、取哪几张,**因模型而异且方向可反**。

## 7. 局限与待做

- 状态集条件于 recency-2 成功,伤害是保守方向的估计,"救回"被低估;记忆关键状态另由 B 路构造任务覆盖。
- 步级动作复现 ≠ 任务成功;闭环层面 GUI-Owl 的绝对成功率约 27%(官方 38.2%,8-24 复现 33.3%),环境噪声大,
  任务级验证只能作辅助(recent0 / recent2 / recent8 / random2 四臂在跑)。
- 三个相关的候选变量(原始 token 负载 / MRoPE 有效位移 / 图块数)只分开了两个:等 token 文本已排除"纯 token 负载";
  "图块数 vs 图 token"(把 2–3 张灰图拼成一张)与 MRoPE 位置记账待做;是否可训练修复(长窗口 SFT)不诊断,暂不做。
- "放指令之前"只证明了安全,尚未证明**有用**:要在"必须看老帧"的状态上比 N=0 / 参考轮在前 / 在后(B 路 pilot 任务与 Venus 去文本口径的远帧子集)。
- 终止有轨迹后段的混杂:按步深分层与配对检验待补(`deploy_by_depth.py`)。
- 注意力探针只做了 40 态、单模型;终止的逐 token 概率曲线(terminate 的 logit 随指令后图数变化)可以作为更直接的机制图。
