## 0. 问题
给 GUI agent 历史截图为何反而有害?(现象见 `rl/harm/README.md` §0)

## 1. 当前生效的判断
- H0(现象):冻结 GUI-Owl-1.5-8B 在 MobileWorld 上,任何额外历史图都降低步级动作复现率;伤害随图与任务的相关性降低而增大,但相关图也伤害。
- 假说池:H1 视觉稀释;**H2 时序歧义(支持,机制 B)**;H3 token 数(**排除**);H4 过期动作复读;**H5 长交错历史诱发过早终止(支持,机制 A)**。

## 2. 预注册判据(数据落地前写定)
- **Step 1 伤害 vs N**(`harm_vs_n_chain.sh`,GUI-Owl 底座,337 态,两协议,recN 与 irrN,N∈{0,1,2,3,4,6}):
  P1.1 V(recN) 随 N 单调下降(Spearman ρ<0,配对 bootstrap CI 不含 0);
  P1.2 每个 N 上 V(irrN) ≤ V(recN)(无关图伤害 ≥ 相关图);
  P1.3 去文本轨迹协议下伤害减弱或反号(与 Venus 现象一致)。
- **Step 2 错误分类**(`harm_error_classes.py`,零 GPU):
  P2.1 某一类占伤害状态的多数(>50%);P2.2 该类在 irrelevant 与 recency 两条件下占比一致(同一机制)。
- **Step 3 干预**(同一链里的 rec2_mark / rec4_mark、rec2_blank / rec4_blank):
  P3.1 若 recN_blank 的伤害 ≈ recN,支持 H3(token 数效应);若 blank 伤害 ≈ 0 而 recN 伤害显著,排除 H3;
  P3.2 若 recN_mark 显著降低伤害,支持 H2;
  P3.3 注意力测量(待做,需要 HF transformers 前向)。

- **提示完全无效**:terminate 占比原样 73% → hint 73%,复现率不变。过早终止对指令不敏感,不是"读了任务描述后的判断"。
- **assistant 回复原文是承重的**:N=2 时只留 conclusion 一行就掉 19 个点——最近 turn 的原文(含 `<tool_call>` JSON)是模型复现自己动作的
  主要线索;去掉它,终止确实减少(73 → 48 / 10%),但其它错误暴增,总体更差。
- 结论:H5 的诱因是 **≥4 个带原文的 assistant turn 的堆叠**——模型在长的"Action: … <tool_call>"序列后模式补全出"收尾/终止";
  它不能靠提示压制,也不能靠删文本消除(删了就失去复现线索)。**GUI-Owl 原生协议的默认 N=2/3 恰好是这条病理曲线的最优点**,
  "给更多历史 turn 更差"是终止病理,不是记忆容量问题。训练侧假说(待验):GUI-Owl 的训练窗口只有短交错历史,长窗口 OOD。
- 方法含义:要检索老帧,不能通过"多保留 turn"实现(会触发 H5),必须走**不增加 assistant turn 的格式**——即 hybrid(额外带标记的图)。
  hybrid 正在跑(`format_chain.sh`)。

- **部署忠实布局的自复现 = 93.5%**(rec2,T=0)⇒ 布局重建成功(标注器布局只有 55.8%,差异来自布局而非模型)。
- **机制 A(部署布局,非单调)**:历史图 N=1–3 **有益**(71.8 → 93.5),N≥4 **骤降**(70.0 / 72.4,低于 N=0)。骤降的失败形态是
  **过早终止**:rec4 / rec6 的错误里 73–74% 输出 "Terminate, task finished";rec2 对→rec4 错的 82 个状态里 85% 是 terminate;
  irr4 也 52%。目标动作没有一个是 terminate。⇒ **长的交错历史让模型误以为任务已完成**(新失败模式,与 H1–H4 都不同,记为 H5)。
  按历史长度分层骤降一致(5–9 帧 70.0、10–19 帧 61.2、20–29 帧 69.8、30–50 帧 75.7),不是构造问题。
- **机制 B(标注器布局,单调伤害)**:任何额外图都降低复现(62.9 → 54.6–59.3),无关图更甚(45–49)。两个干预都把它**恢复到 N=0 水平**:
  PAST/CURRENT 文本标记(63.5 / 64.4)与同 token 数灰图(64.4 / 63.8)。灰图有效 ⇒ **不是 token 数**(排除 H3);标记有效 ⇒
  **时序歧义**(H2):图连排在文本前、无轮次结构时模型分不清哪张是当前屏。部署布局的交错轮次天然消歧,所以 N≤3 反而有益。
- 无关图在部署布局下也有益(irr2 84.6 > rec0 71.8):部署布局里 N 同时控制"多少张图"与"多少个 turn 的 assistant 原始回复
  被保留",结构贡献约 +13,内容再 +9(rec2 − irr2)。**"真实帧 > 无关帧 9 个点"在部署布局下成立** ⇒ 主线"截图无额外信息"
  是标注器布局的伪影,须在部署布局下重测裁判帧(已发射)。
- 去文本轨迹(标注器布局):N 对复现率几乎无影响(31–34),真实 > 无关约 +7~+10;GUI-Owl 没有文本轨迹时整体崩到 32%。
- 判据:P1.1(单调下降)在部署布局**不成立**(非单调),在标注器布局成立;P1.2(无关 ≤ 真实)两布局都成立;P1.3 部分成立;
  P3.1 灰图≈N=0 ⇒ 排除 H3;P3.2 标记显著降低伤害 ⇒ 支持 H2。
- 论文骨架据此改为:(i) 现象:视觉历史的价值随**呈现方式**与**数量**非单调变化;(ii) 机制 B 时序歧义 + 干预;(iii) 机制 A 长历史
