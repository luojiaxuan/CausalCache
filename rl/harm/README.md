# history-harm:为什么给 GUI agent 历史截图反而有害?(机制探索线,2026-09-05 起)

分支 `history-harm` 从 CausalCache `main` 分出,专门深挖一个反常现象。方法论参照 ICLR 论文
*More Thought, Less Accuracy?*(arXiv 2509.25848)的探索流程:**现象站稳 → 错误分析 → 机制假设 → 干预检验 → 方法 → 消融**,
每一步接住上一步留下的问题。目标是一篇 ML 会议风格的机制论文,不是系统论文。

## 0. 现象(2026-09-06 更新:呈现方式决定历史截图是益是害,且随数量非单调)

冻结 GUI-Owl-1.5-8B,MobileWorld,337 个自一致状态(recency-2 成功轨迹中取步;采样条件于成功,见台账),步级动作复现率(%)。
图见 `fig1_harm_vs_n.png`(伤害 vs N,四种布局 + Venus)与 `fig2_trigger.png`(剂量 × 放置:只有指令之后的图块触发终止;
同剂量放指令之前、等 token 文本、拼成一块都不触发),数据 `harm/harm_vs_n_base_*.jsonl`、`harm/dose*_base.jsonl`、`harm/reply_pattern*_base.jsonl`。

| 历史图数 N(官方榜单协议为 N=0;recency-2 是本项目 B=2 约定) | **部署布局**(交错多轮,agent 真实所见) 真实 / 无关 | 标注器布局(图连排在前 + 全部 conclusion) 真实 / 无关 |
|---|---|---|
| 0 | 71.8 | 62.9 |
| 1 | 87.8 / 81.3 | 54.6 / 48.4 |
| 2 | **93.5** / 84.6 | 55.8 / 49.0 |
| 3 | 90.2 / — | 54.9 / 46.3 |
| 4 | **70.0** / 68.2 | 59.3 / 48.1 |
| 6 | 72.4 / — | 58.2 / 45.4 |

三个事实:
1. **部署布局下历史图先益后害**:N=1–3 把复现率从 71.8 抬到 93.5,N≥4 骤降到 70 以下。骤降的形态是**过早终止**——N=4/6 的错误里
   73–74% 输出 "Terminate, task finished",而目标动作无一是 terminate(机制 A,H5)。
2. **无轮次结构地连排历史图,任何图都有害**(标注器布局,62.9 → 55–59;无关图 45–49)。给历史帧加一行 PAST/CURRENT 文本标记,
   或把历史帧换成同 token 数的灰图,伤害**完全消失**(63.5–64.4)。灰图有效 ⇒ 不是 token 数;标记有效 ⇒ **时序歧义**(机制 B,H2)。
3. 部署布局下真实帧比无关帧多 9 个点(93.5 vs 84.6),结构本身值 13 个点(84.6 vs 71.8):历史图的价值 = 结构 + 内容两部分。

伤害状态的错误形态(标注器布局)与图的内容无关:过期动作复读 30–41%、坐标漂移 37–61%、类型漂移 10–16%,三种给图条件下占比相同。

**机制 A 的触发物是什么(2026-09-06 下午的干预链,全部在部署布局、337 态):**
- 三种直接干预都压不住终止:首条消息加"任务未完成"提示(73% → 73%)、把指令原文重复到当前屏旁边(70.0 → 71.8,终止占比 73 → 56% 但
  总体不变)、回复只留一行 conclusion(终止 73 → 48%,但复现率掉 14 点)。注意力探针里指令文本的注意力确实随 N 从 26.5% 掉到 8.1%,
  但补回指令无效,所以"目标稀释"只是相关(H5′ 降级)。
- 同样 5 张图的四种放法,终止率从 0.3% 到 22%;同样 2 轮的三种放法,从 0.7% 到 20%——**轮数和图数都预测不了终止**。能把所有条件排齐的
  变量是"指令消息与最近两轮之间堆了多少内容":rec3 夹 1 轮不塌、rec4 夹 2 轮塌;把 2 张标记老帧塞进指令消息本身也塌(hybrid-first,20%);
  同样的老帧放在当前帧旁边(hybridlast)或作为参考轮放在指令**之前**(hybridturn)都不塌(≤0.7%),复现率 83–88%。
- 分辨实验:同样的参考轮改插到指令**之后**(hybridturnin)就塌(终止 20.5%,复现 73.6%),与 rec4 一样;把 rec4/rec6 的早期动作回复换成
  "Noted" 只把终止从 22/20.5% 降到 16.6/11.9%。**触发物是指令之后的历史块长度,不是回复里的动作序列**;回复内容只调节幅度。
- 再收窄:把插在指令之后的参考轮换成**灰图**(同 token、无内容)照样塌(终止 19.9%);换成**纯文本**(老步骤的 conclusion)完全不塌
  (0%,复现 93.8%)。所以是**指令之后的图块计数效应,与图内容无关**。
- 剂量曲线是**阶跃**:指令之后 1 张灰图无事(92.6),2 张就塌(72.4,终止 20.8%),3–4 张不再加深;合上 rec3 不塌 / rec4 塌,
  规则是"从指令消息数起、到最近两轮之前,图块 ≥3 就塌"。等 token 的纯文本(4 块 ≈ 4 张截图)只有 7.7% 终止——主效应是图块数,
  文本长度只贡献一个小的渐变距离效应。同剂量放**指令之前**:1–4 张灰图都无害(90.5–92.3,终止 ≤0.9%)——放置是全部。禁掉 terminate 的全部拼法后复现率回到 87.5–89.6(回收七至八成)——塌陷是选择性的"假完成"模式,不是能力破坏;拼图对照定案:2–4 张灰图拼成**一块**只 3–4% 终止(分开放 16–21%),token 与位置位移相同——**变量是图块数,不是视觉 token 量**。
- 块的定义:每块只有 0.2 张截图高的两个图轮照样塌(17.8%);3 张图放进一个 user 轮不塌(3.9%),塞 3 张才塌(22%)。
  **主触发 = 指令之后带图的 user 轮数 ≥3,一个格式事件**;图的大小、内容、token、位置位移、回复文本都不是变量。
- 方法含义:在 GUI-Owl 上检索老帧**不能**靠多保留轮实现;放在指令之前的参考轮(hybridturn)已把裁判帧的复现率从"多保留轮"的约 70% 抬到
  87–88%,接近 recency-2 的 93.5%——这是"视觉历史不该默认取最近图"在该模型上可行的呈现方式。

跨模型:UI-Venus-2-9B **没有**这条病理——N=0→1 复现率 88.7→91.6 后饱和,N=4/6/8 不掉、无早停激增,真实帧比无关帧高 4–7pp
(图第五面板);去掉文本轨迹后,裁判选的老帧比无关帧多救回 +20~+31pp、比最近两帧好 17–27pp。视觉历史该取多少、取哪几张,**因模型而异且方向可反**。
现役解释:GUI-Owl 官方协议只给 1 轮历史,"指令之后跟一长串已完成的(图, 动作)"对它是训练分布外的输入,模型按模式补全出"收尾";
Venus 原生就是多轮协议,没有这个盲区。

**警示**:此前主线在标注器布局下得出的步级结论(recency 有害、裁判帧≈无关帧、训练后真实≈无关)须在部署布局下重测——裁判帧的重测在跑。

## 1. 研究路线(每步预注册判据,写进本目录 `docs/`)

**Step 1 现象站稳(普遍性)**:换模型(GUI-Owl-1.5-8B/32B、UI-Venus-2-9B、Qwen3-VL-8B、Qwen3.8-27B、MAI-UI 等)、
换基准(MobileWorld、AndroidWorld、GUI-Odyssey 离线、OSWorld 截图)、扫历史图数 N=0..6、两种协议(保留/去掉文本轨迹)。
输出:一张"伤害 vs N"的折线族(模型 × 协议)。判据:伤害在 ≥3 个模型 × ≥2 个基准上可复现。

**Step 2 错误分析(伤害是什么样的错)**:把"不给图对、给图错"的状态拆类——
(a) **今昔混淆**:点击坐标落在只存在于历史帧的控件上(可用历史/当前屏的 UI 树或 caption 机器判定);
(b) **过期动作复读**:重复了历史某步的动作;
(c) **指令遵循退化**:动作类型/格式错;
(d) 其它。判据:某一类占伤害的多数。

**Step 3 机制假设 + 干预检验**(状态:H1 视觉稀释排除、H3 token 数排除、H2 时序歧义支持、H5 长历史诱发终止支持、H5′ 目标稀释仅相关;
现役问题是 H5 的触发物,见 §0)——候选假设——
(H1) **视觉稀释**:当前屏的图像注意力随历史图数下降(仿照该论文的 attention-to-image 曲线,逐层测);
(H2) **时序混淆**:模型分不清哪张是当前;
(H3) **上下文长度效应**:与图无关,纯粹是 token 数。
对应干预:给历史帧加显式"PAST"标记/边框/时间戳(测 H2);把历史帧降分辨率或换成空白/噪声图但保持 token 数(测 H3 vs H1);
当前图放最前 vs 最后(位置效应);测注意力分布(H1)。判据:哪个干预让伤害显著下降,机制就指向哪里。

**Step 4 方法 + 消融**:按机制设计训练目标(例如对历史帧引起的错误加权、或在训练中显式教"当前屏优先"的对比样本),
或推理时修复;主实验(伤害是否消失、救回是否上升)+ 消融(每个设计部件的作用)。

**图表**:每张图承担一个证据职责——现象图(伤害 vs N)、错误类型饼图、注意力曲线、干预对照柱、方法主表、消融表。
