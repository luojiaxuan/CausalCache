# HGKV 效应分解:四分之三是均匀抬升,选择性只对"挖出来的那类帧"有效

> **结论:k 错配假设不成立(效应不随 k 衰减)。真正的问题是目标函数允许适配器
> 用"均匀抬升"充数——实测均匀成分占总效应的 73–77%,而对一般远端帧的选择性
> 只有 +0.0027,比对训练时挖出的目标相关帧(+0.0224)小 8.2 倍。**

## 测法(纯离线,不需 GPU)

同一批集合有两套真值打分:

| 语料 | 打分策略 |
|---|---|
| `selector-v4-merged/sets` | 挂 HGKV(ckpt `572092c2…`) |
| `selector-v4-frozen/sets` | 冻结策略(`checkpoint_sha256: "frozen-bypass"`) |

相减即适配器效应 **A(S) = U_hgkv(S) − U_frozen(S)**,共同集合 **68,849** 条。
按 **k = |S \ Recent-|S||** 分层。k=0 表示该集合恰好是 Recent-|S|,
**适配器理应中性**(drift cap 的设计目标),是内部对照。

## 结果一:效应不随 k 衰减 → k 错配假设否定

| k | n | A(S) | CI95 |
|---|---|---|---|
| **0** | 3,358 | **+0.00917** | [+0.00874, +0.00960] |
| 1 | 38,825 | +0.01191 | [+0.01178, +0.01205] |
| 2 | 25,877 | +0.01256 | [+0.01240, +0.01272] |
| 3 | 789 | +0.01241 | [+0.01161, +0.01322] |

按集合大小分层同样平坦(B=2/3/4 各自的 k=1→k=2 都是持平或微升)。

**"训练只教 k=1、部署走到 k=4 导致失配"这条假设不成立。**

## 结果二:四分之三的效应与内容无关

k=0 本应中性,实测 **+0.00917**,达到 k=1 效应的 **77%**:

| | 值 | 占总效应 |
|---|---|---|
| 均匀成分(k=0) | +0.00917 | — |
| k=1 选择性(k=1 − k=0) | **+0.00274** | **23%** |
| k=2 选择性 | +0.00339 | 27% |

> **2026-08-02 订正:原文这里写"论文 Table 3 的 $|A_r|=0.0088$ 与 k=0 的 +0.0092
> 几乎相同,两个独立来源相互印证"——这是错的,两者不是同一个量,数值接近是巧合。**
>
> 把 v4 适配器用官方门控脚本在 desktop DiD held-out(94 组)上重打后:
> 选中的 `lora-step250` 的 $A_r = -0.00079$,**CI [−0.0031, +0.0019] 跨零**;
> v4 训练日志里的 `adapter_on_recent` 也只在 ±0.003 波动。
> 也就是说 **DiD 语料的 recent 臂上根本没有 +0.009 的均匀抬升**。
>
> 本页的 k=0 = +0.0092 测的是**另一件事**:selector 的 set 打分语料上,
> 任意"恰好等于 Recent-|S|"的集合所受的适配器效应。两者语料与打分管线都不同。
>
> **这个偏移不是两次运行之间的系统性差异造成的**:两套语料的 $U(\emptyset)$
> 在全部 5,335 个状态上**逐位相同**(差值 mean=sd=0,0% 有差异),
> no-history parity 精确成立。所以 +0.0092 是真实的适配器效应。
>
> **推论(重要)**:drift cap 约束的是 DiD recent 臂的 $A_r$,而那里本来就≈0
> ——`[|A_r|-\epsilon]_+` 在 $\epsilon=0.02$ 下**恒为 0,没有梯度**。
> 均匀抬升长在 cap 看不见的地方(任意集合上),**所以收紧 $\epsilon$ 修不了它**。
> 详见 `data/results/hgkv_v6_capsweep_v1/`。

## 结果三:选择性只对"挖出来的那类帧"有效

| 对象 | 选择性 |
|---|---|
| 训练时挖出的**目标相关帧**(论文 DiD `A_s − A_r`) | **+0.0224** |
| **平均远端帧**(本次 k=1 − k=0) | **+0.0027** |
| 比值 | **8.2×** |

部署时 selector 挑的是"预测效用高"的帧,**不是训练时挖的 witness 那一类**,
因此实际拿到的选择性在 +0.003 量级,而拿到的主要是对决策无用的均匀抬升。

## 为什么会这样:目标函数的两个漏洞

$$\mathcal L = [m-(A_s-A_r)]_+ + [m-A_s]_+ + [m-(A_s-A_n)]_+ + \lambda_{\mathrm{cap}}([|A_r|-\epsilon]_+ + [|A_n|-\epsilon]_+) + \lambda\lVert\Delta W\rVert^2$$

**漏洞 1:drift cap 管不到均匀抬升。**(2026-08-02 修正表述)
原来的说法是"$\epsilon=0.02$ 太松,贴着 cap 加均匀抬升最省力"。实测后更准确的说法是:
**cap 根本没在约束这件事**。DiD 语料 recent 臂的 $A_r$ 实测只有 ±0.003
(held-out 甚至跨零),$[|A_r|-\epsilon]_+$ 在 $\epsilon=0.02$ 下**恒等于 0**,
整项没有梯度。而均匀抬升出现在**任意集合**上(本页 k=0 的 +0.0092),
那不在 cap 的约束范围内。

第二项 $[m - A_s]_+$ 仍然**直接奖励 $A_s$ 变大**,均匀抬升是把 $A_s$ 做大的最廉价方式
——奖励在,约束不在,所以模型走这条路。**修法不是收紧 $\epsilon$(约束一个已经≈0
的量),而是把约束加到集合分布上**:按状态中心化,或对整个候选/集合分布的平均效应
罚项,使"所有集合一起抬高"在目标上不可能得分。

**漏洞 2:目标是三选一,不是排序。** 每组只对比 `relevant / recent / wrong` 三个臂。
适配器**从未被要求在多个看起来都合理的远端帧之间分高下**——而这正是部署时的任务。
`wrong` 臂是"年龄匹配但后续动作不等价"的帧,与"合理但次优"的帧不是一回事。

## 修法建议(按预期收益排序)

1. ~~**收紧 cap**:$\epsilon$ 降到 $m$ 的 1/5(如 0.002)~~ —— **2026-08-02 撤回。**
   实测 $A_r$ 在被约束的语料里只有 ±0.003,cap 项恒为 0、无梯度;
   收紧到 0.002 也只在约一半的窗口上激活,且改变的是一个与 +0.0092 无关的量。
   已跑的 v6 cap 三臂只作为"该杠杆无效"的经验确认,不作为修法。

   **改为:按状态中心化 / 对集合分布的平均效应设罚项。** 即把
   $\bar A(\text{state}) = \mathbb E_{S}[A(S)]$ 从所有臂里减掉,或加
   $\lambda\lvert\bar A\rvert$ 一项,使"所有集合一起抬高"在目标上**不可能得分**。
   与原来的 cap 不同,这一项作用在**集合分布**上,正是 +0.0092 所在的地方。
   成本:改目标 + 重训,数小时。
2. **把三选一换成候选池上的排序损失**:对每个状态,在**整个候选池**上按真值边际
   排序(数据已有:单例分 52,823 条覆盖全池)。这直接对齐部署任务。
   成本:改数据管线 + 重训。**收益最大。**
3. rank / 层数(r=8→32、last-8→last-36):次要。已有的 last-36 尝试离线更好但
   闭环无差别,与本文诊断一致——**加容量不解决"目标允许走捷径"的问题**。
