# 部署配置诊断:选 checkpoint 的口径不是上线的口径

## 问题

"离线 DiD 涨、闭环不涨"。查代码发现两处**离线-部署不一致**,本文档测量它们的代价。

## 不一致一:readout 塔训练时开、部署时关

selector 是可加双塔:`score = cheap(x) + readout(r) · mask`。

- `cheap`:28 维手工特征(20 候选 + 8 集合上下文),42,817 参数;
- `readout`:448 维 HGKV 反事实读出(8 层 × 8 kv-head × 7 统计量),28,801 参数。

读出特征**必须挂着探针跑一遍**才能算出来,而探针不上线。两个 serve 脚本因此把
readout 塔以 mask=0 关断——这是有意设计(可加结构的红利)。实测确认:两台主机
**154 条真实服务器启动记录,`readout_online` 全部为 false**,无一例外。

**但训练与 dev 评测的 `_fwd` 一直带着读出前向**,`best_epoch=10` 这个 checkpoint
是按**带读出**的 dev top1-regret 0.0849 选出来的。部署配置下的指标从未测过。

## 测量(同一 bundle、同一 dev、只切 mask)

| 指标 | readout 开(训练口径) | readout 关(**部署口径**) | cheap-only 独立训练 |
|---|---|---|---|
| dev top1-regret | 0.0874 | **0.0958** | 0.0939 |
| dev edge MSE | 0.01035 | **0.01615**(+56%) | — |
| **replay_gain_b2** | **+0.0113** | **+0.0023** | +0.0051 |
| replay_gain_b4 | −0.0369 | −0.0461 | — |
| 模型自选集合大小分布 | {1: 390, 2: 20} | **{1: 410}** | — |

(开的口径 0.0874 与原训练日志的 0.0849 接近;差异来自本次 dev 集较小
——15,664 条边 vs 原 20,503,因 h00 当前只持有部分 sets 分片。配对对比不受影响。)

**两条结论**:

1. 部署配置的排序质量**退回 cheap-only 水平**(0.0958 vs 0.0939),读出带来的
   −9.6% regret 优势在上线时全部消失;
2. 更关键的 `replay_gain_b2`(在教师树上真实走一遍的效用增益)**从 +0.0113 掉到
   +0.0023,不足五分之一,且低于 cheap-only 的 +0.0051**。也就是说部署配置下的
   selector **比一个从头训练的纯 cheap 模型还弱**——cheap 塔一直有残差兜底,
   从未被要求独立成立,单独拿出来是失配的。

## 不一致二:模型只想选 1 张,部署强制选 4 张

`model_set_size_dist` 显示:部署配置下模型在回放中 **410/410 全部只选 1 张帧**
(带读出时也仅 20/410 想选 2 张)。训练日志里 `replay_gain_b4` **每个 epoch 都为负**
(−0.038 / −0.026 / −0.028 / −0.030 / −0.031),即模型认为第 3、4 张的边际是负的。

而部署侧 beam 搜索是 `for _ in range(budget)`,**无条件走满 B 层**,最后
`chosen = sorted(level[0][0])` 取满 B 个:

```python
for _ in range(budget):        # 恒等于 B,不因边际转负而停
    ...
chosen = sorted(level[0][0])   # 恒为 B 个
```

**后果:B=4 时四个槽位里有三个装着模型自己判定为负边际的帧,并且它们挤掉了三张
recent 帧。** 这与"离线选择性为正、闭环不涨"完全吻合:被正确识别出来的那 1 张
有用帧的收益,被另外 3 张负收益帧的损害抵消。

## 这不是"训练不足"

v4 的学习曲线诊断早已判定:25/50/100% 三点全平、train/dev MSE 无缺口 →
**偏差主导而非方差主导**。加标签、训更久都不会有帮助;而本轮测量显示最优 epoch
(10)在两种口径下的排序也没有本质冲突。瓶颈是**特征表达力**与**上述两处口径失配**,
不是标签量或训练时长。标签量本身也已确认充足(5,335 状态全覆盖,147,296 唯一边)。

## 可操作的三条(按预期收益/成本排序)

1. **按部署口径选 checkpoint / 直接蒸馏**:用 mask=0 的 dev 指标重选 epoch,或把
   带读出的双塔当教师、蒸馏一个纯 cheap 学生。成本:一次 CPU 重训。
2. **放开 exact-B**:允许边际转负时提前停止,剩余槽位用 recent 补齐
   (仓库已有 `eval_selector_v4_fill_to_b.py` 与 `filltob_*` 实验,可复用)。
   这直接消除"三个负收益槽位"。注意这会改变"固定视觉预算"的叙事口径,需在论文中
   明确:预算仍为 B,只是分配规则从"必须选满 B 个远端帧"变为"选到边际转负为止,
   其余留给 recent"。
3. **增强特征**:候选帧图像 embedding(可离线预计算并缓存,不随 beam 重复)
   + 当前截图 + 任务目标,每步只需一次视觉编码。这是针对"偏差主导"的正面解法,
   但成本最高。
