# v4 集合标签覆盖率核账:语料是完整的,只是跨机分片存放

## 起因

排查 selector 标签量时,我在 hyper01 上统计 `selector-v4/sets/`,得到 3,992 状态 /
110,104 唯一边,与本目录 README 记载的"5,335 状态、147,297 唯一行、skipped=0"不符。
据此我一度判定"集合打分只覆盖 75%,还有 1,343 个状态从未打分",并把这个错误写进了论文。

**这个判定是错的。语料完整。**

## 事实

集合打分当初跨两台机器分片执行,**每台只保留自己那部分分片文件**(h00 有
`shard*-of-015` 8 个 + `shard*-of-032` 16 个,h01 是另一组)。任何单机统计都是低估:

| 位置 | 状态 | 唯一集合边 |
|---|---|---|
| hyper00 `/data/runs/selector-v4/sets` | 3,662 | 100,925 |
| hyper01 `/bigdata/mw/runs/selector-v4/sets` | 3,992 | 110,104 |
| 交集 | 2,319 | 63,733 |
| **并集** | **5,335** | **147,296** |

并集与 README 的 5,335 / 147,297 完全吻合(边数差 1 为 fingerprint 行)。
**"仅 h00 独有"恰好是 1,343 个**——正是我误当成"缺失"的那批。

frozen 教师变体同理:h00 22,903 边、h01 88,781 边,**并集 88,781**(h00 是 h01 的子集),
即 88,781 / 147,296 = **60.3%**,与补充材料原文"60% 状态子集"一致。我曾把它改成
"81%",同样是单机统计造成的。

## 结论

1. **v4 集合标签语料完整**:5,335 状态全覆盖,skipped=0,README 一直是准确的;
2. **frozen 变体确为 60% volume**,论文原文正确,我的"更正"是错的,已回退;
3. **原任务"补齐 ubuntu 剩余 1,343 个状态"前提不成立**,该任务作废。win/mac 的
   17,452 个状态仍然未挖,那是另一件事(跨 OS,迁移性未知)。

## 教训

**跨机分片的产物必须先取并集再统计,单机数字一律视为下界。**
判断"某某缺失"之前,先确认该产物是不是分片存放的——本仓库里 selector 标签、
OSWorld 收割文件都是这种形态,而它们的文件名(`shard*-of-015` 与 `shard*-of-032`
两套并存)本身就是分片的信号。

配套动作:统计脚本 `dump_v4_states.py` / `count_v4_sets.py` 必须在两台机器上都跑
并合并,不能只跑一台。
