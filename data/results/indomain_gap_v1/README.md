# 同域(OSWorld)为何不涨:根因是部署配置下的边际校准崩了

## 摘要

同域闭环 selector 相对 Recent-4 只有 +1.11pp(p=0.30),这是论文最容易被质疑
"方法有无意义"的地方。本轮调查得到三条结论:

1. **不是"没头寸"**。仓库原解释是"OSWorld 相关状态多在近期窗口内,recent 已吃掉
   收益"。但 selector 与 recent 的**不一致对是 25:21**——它做了 46 个任务的不同
   决策,只是赢输几乎抵消。**这是精度问题,不是头寸问题。**
2. **损失有清晰的域结构**:收益集中在跨应用/图形类,损失集中在单应用文档类。
3. **根因是部署配置下模型的边际预测系统性偏负**:实测 97.4% 的可触发步**连一个
   候选的预测边际都不为正**。原语义(无阈值、恒取 B 个)靠 argmax 取"最不负"的
   掩盖了这一点;一旦加上"只提升边际 > 0"的弃权阈值,选择器几乎完全关闭。

## 一、不是没头寸:域级拆分

同域五臂(361 全满员):B0 19.94% / Recent-4 32.69% / HGKV-recent 32.96% /
**CausalCache-LA 34.07%** / CausalCache-P 32.69%。LA vs recent +1.11pp,
CI [−2.49,+4.71],不一致 **25:21**。

| 净收益 | 域(赢:输) |
|---|---|
| **正** | gimp 4:1、multi_apps 4:2、calc 4:2、os 3:1、vlc 2:0、chrome 4:3 |
| **负** | **writer 0:4**、impress 2:4、thunderbird 0:2 |

收益在跨应用与图形类,损失在单应用文档类——与 MobileWorld 的
memory-critical / control 结构同形,区别是**同域的 control 类不是无效而是被伤害**。
writer/impress/thunderbird 这类任务最依赖刚编辑过的几屏,一旦被远端帧挤掉就砸。

顺带排除两条备选假设:
- **不是 witness 太弱**:两遍 P 在同域 32.69%,**不比**单遍 LA 的 34.07% 好;
- **不是触发率**:100 步跑批里池子 < 预算只占 9.5%。

## 二、弃权实验(τ=0):空转,但它暴露了根因

改动只有一处:`--selector-min-marginal 0`——只提升预测边际 > 0 的候选,不足 B 个
用最近帧补齐(预算仍为 B=4)。OSWorld 15 步全量 361,h00+h01 六卡 24 分片。

**结果:29.09%,比 Recent-4 低 3.88pp,比无弃权 selector 低 4.99pp。**

审计日志揭示了为什么这个数不能按字面读(2,917 步):

| 情形 | 步数 | 占比 |
|---|---|---|
| 池子 < 预算,不触发 | 1,305 | 44.7% |
| 触发但 **promoted = 0**(完全弃权 → Recent-4) | 1,570 | 53.8% |
| promoted = 1 | 41 | 1.4% |
| promoted = 2 | 1 | 0.03% |

**可触发的 1,612 步里,97.4% 连一个候选的预测边际都不为正。** 该臂在 98% 的步上
与 Recent-4 行为完全相同——它本质上是重跑了一遍 Recent-4,测不出弃权的效果。

**因此这不是"弃权有害"的证据,而是"部署配置下边际预测系统性偏负"的证据。**
τ=0 只是把一个本来被 argmax 掩盖的校准缺陷暴露了出来:

- 无阈值时:所有候选都是负的,argmax 仍挑"最不负"的一个,看起来在正常工作;
- 有阈值时:全部低于 0,全部弃权。

这与离线诊断一致(`../selector_deploy_config_v1`):部署配置下 `replay_gain_b2`
从 +0.0113 掉到 +0.0023、模型只想选 1 张帧——现在看在真实部署池上连 1 张都不想选。

**修复顺序因此被这轮实验确定:必须先修校准(按部署口径训练/选 checkpoint),
弃权阈值才可能起作用。** 单独上弃权是空转。

## 三、意外收获:OSWorld 15 步的单轮噪声地板

弃权臂与 Recent-4 在 98% 的步上行为相同,任务级却:

| | 值 |
|---|---|
| 一致 | 309 / 361 |
| 弃权臂独赢 | 19 |
| Recent 独赢 | 33 |
| **翻转率** | **14.4%** |
| 净差 | −14 个任务 = −3.88pp |

**两个近乎相同的策略,任务级翻转 14.4%。** 这比此前从 30 步跨机重复任务估的
7–9% 更严格(15 步 episode 短,单个动作分叉更容易改变结局)。

**推论:OSWorld 15 步单轮上 ±4pp 以内的差异不可解释为效应。** 这直接意味着原来
那个 "sel1p vs recent +1.11pp" 本来就在噪声里,不能作为"同域有小幅正收益"的证据,
同样也不能作为"同域无效"的证据——**这个基准在单轮口径下没有分辨这个量级的能力。**

要在同域得到可判定的结论,只有两条路:多轮平均(至少 3 轮),或改用步级/效用级
指标而非任务成功率。
