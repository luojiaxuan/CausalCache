# 同域不涨:根因链与修复(夜间调查完整记录)

> 一句话:**同域头寸很大(oracle 比 Recent-2 多拿 +0.1019 效用),我们的 selector
> 只捕获了 6.5%;而部署配置下它的边际预测被一个常数偏置压到 100% 为负,导致任何
> 阈值/早停判据全部失效。** 不是"方法没意义",是"测量仪对、学生弱、部署链路还有
> 一个可修的校准缺陷"。

## 0. 结论速查

| 问题 | 判定 | 证据 |
|---|---|---|
| "同域没头寸,recent 已吃满" | **否定** | oracle−锚 = **+0.1019**(B=2);selector 与 recent 不一致 25:21 |
| "witness 太弱(单遍)" | **否定** | 两遍 P 同域 32.69%,**不优于**单遍 LA 34.07% |
| "触发率太低" | **否定** | 池子 < 预算仅占 9.5% |
| "标签量不够" | **否定** | 5,335 状态全覆盖、147,296 边;学习曲线三点全平=偏差主导 |
| "训练不足" | **否定** | 早停在 epoch 25/45,train/dev 无缺口 |
| **"部署配置下边际校准崩塌"** | **成立** | cheap 塔单独在 20,503 条 dev 边上**无一预测为正** |
| **"selector 捕获率极低"** | **成立** | 6.5%(B=2,部署口径) |
| **"B=4 是最难展示选择价值的工作点"** | **成立** | oracle 头寸 B=2 +0.1019 → B=4 +0.0366 |

## 1. 不是"没头寸":域级证据

同域五臂(361 全满员):B0 19.94% / Recent-4 32.69% / HGKV-recent 32.96% /
**LA 34.07%** / P 32.69%。LA vs recent +1.11pp(p=0.30),**不一致 25:21**。

若真无头寸,selector 应几乎不偏离 recent。实际改变了 46 个任务的结局,只是赢输抵消:

| 净收益 | 域(赢:输) |
|---|---|
| **正** | gimp 4:1、multi_apps 4:2、calc 4:2、os 3:1、vlc 2:0、chrome 4:3 |
| **负** | **writer 0:4**、impress 2:4、thunderbird 0:2 |

收益在跨应用/图形类,损失在单应用文档类——与 MobileWorld 的 memory-critical /
control 同构,区别是**同域的 control 类不是无效而是被伤害**。

## 2. 教师标签说头寸确实存在

| 教师标签(全量 5,335 状态) | |
|---|---|
| 单例边际为正 | **68.4%** |
| **至少有一个正单例的状态** | **95.3%** |
| 集合边际为正 | 36.8% |

**95.3% 的状态里存在值得恢复的帧。** 再看 oracle 能兑现多少:

| 部署口径 | 模型−锚 | oracle−锚 | 捕获率 |
|---|---|---|---|
| B=2 | +0.0066 | **+0.1019** | **6.5%** |
| B=4 | −0.0346(图数不匹配伪影) | +0.0366 | — |

**头寸随 B 增大急剧收缩**:B=2 的 +0.1019 到 B=4 只剩 +0.0366。Recent-4 已经很强,
选择空间被挤掉——**B=4 恰是最难展示选择价值的工作点**,与补充材料全量表"峰值在
B=2"一致。

## 3. 根因:部署配置下的常数偏置

selector 是可加双塔 `score = cheap(x) + readout(r)·mask`。readout 需要挂探针才能算,
**部署侧恒 mask=0**(154 条真实启动记录无一例外)。实测两个 bundle:

| | 原 bundle | 新 bundle(全量+部署口径选) |
|---|---|---|
| dev 标签为正 | 47.7% | 44.6% |
| 标签均值 | +0.0076 | −0.0004 |
| **cheap 塔单独均值** | **−0.0778** | **−0.0665** |
| **cheap 塔单独预测为正** | **0.0%**(15,664 条) | **0.0%**(20,503 条) |
| readout 塔 均值 / 标准差 | +0.0625 / 0.031 | **+0.0653 / 0.0021** |
| 两塔合计正比例 | 32.0% | 37.0% |

**readout 塔实质上是一个常数偏置**(新模型里均值是标准差的 31 倍,权重衰减把它压成
了纯截距)。去掉它 = 给每条预测减 0.065,把**全部**预测推到负值。

### 这个偏置解释什么、不解释什么(重要)

**常数偏置不改变 argmax。** 所以它**不解释**原始无阈值臂为何不涨——那个臂每层取最大,
平移不变。它解释的是:

1. **任何阈值/早停判据失效**。τ=0 弃权实验因此空转:2,917 步里 1,570 步(可触发的
   97.4%)连一个正边际候选都没有,该臂在 98% 的步上等同 Recent-4;
2. **离线 `replay_dev` 的早停 `cpred<=0` 立即触发** → "模型只想选 1 张"的假象;
3. **`replay_gain_b4` 恒为负** → 1 张图的集合对 4 图锚,图数不匹配。

排序质量的退化是另一回事,幅度小得多:top1-regret 0.0874(带读出)→ 0.0958(部署)。

## 4. 已实施的修复

### 修复 1:按部署口径选 checkpoint(已完成)

`train_selector_v4_marginal.py --select-by-deploy-config`:早停与最优快照改用
readout mask=0 的 dev 指标。在**全量合并语料**上重训(见 §6 的语料坑):

| | 原 bundle | 新 bundle |
|---|---|---|
| 部署口径 top1-regret | 0.0958 | **0.0918** |
| 部署口径 replay_gain_b2 | +0.0023 | **+0.0066**(2.9×) |
| cheap-only 独立训练基线 | 0.0939 / +0.0051 | — |

新 bundle 的部署口径 replay_gain **首次超过 cheap-only 基线**。有效,但幅度有限。

### 修复 2:弃权 + 校准截距(已实现,闭环验证中)

`serve_osworld_official_policy.py` 新增:
- `--selector-min-marginal τ`:只提升预测边际 > τ 的候选,不足 B 个用最近帧补齐
  (预算仍是 B,只是不强制把槽位交给远端帧);
- `--selector-score-offset`:补偿 readout 缺席造成的常数偏置。
  新 bundle 的均值匹配最优截距 = 标签均值 − 预测均值 = **+0.0661**。
- 审计字段 `promoted` / `filled_recent` / `k_off_recent`,否则无法判读弃权是否触发。

**顺序不可颠倒**:先修校准,弃权才有意义。单独上弃权是空转(已实证)。

### 修复 3:特征增强(未做,但有了新的判断)

新 bundle 里 readout 塔退化成近乎纯常数(std 0.0021),说明**两塔可加结构下 448 维
读出基本没被利用**。这修改了修复 3 的预期:问题可能不只是"特征弱",而是
**这个架构无法利用高维特征**。若要上图像 embedding,应同时考虑换架构
(如让候选特征与当前状态做交互,而非可加残差)。

## 5. 意外收获:OSWorld 15 步的单轮噪声地板

τ=0 弃权臂与 Recent-4 在 **98% 的步上行为完全相同**,任务级却:

| | |
|---|---|
| 一致 | 309/361 |
| 弃权臂独赢 / Recent 独赢 | 19 / 33 |
| **翻转率** | **14.4%** |
| 净差 | −3.88pp |

**两个近乎相同的策略,任务级翻转 14.4%。** 比此前从 30 步跨机重复任务估的 7–9% 更严格
(15 步 episode 更短,单个动作分叉更易改变结局)。

**推论:OSWorld 15 步单轮上 ±4pp 以内不可解释为效应。** 原来那个"同域 +1.11pp"
本就在噪声内——**它既不能证明同域有效,也不能证明同域无效**。要下结论必须多轮平均,
或改用步级/效用级指标。这一条对审稿防守很关键:与其辩解"同域为何不涨",不如先说明
**单轮口径没有分辨这个量级的能力**,并给出效用级的捕获率证据(6.5%)。

## 6. 语料坑(会误导任何重训)

selector 标签**跨两台机器分片存放**,且两边是**不同的分片方案**(h00:
`-of-015`/`-of-032`;h01:`-of-007` 等),仅 2 个文件重合。单机统计:

| | 状态 | 集合边 | 读出覆盖 |
|---|---|---|---|
| 仅 h00 | 3,662 | 100,925 | 0.80 |
| 仅 h01 | 3,992 | 110,104 | — |
| **并集** | **5,335** | **147,296** | **1.00** |

已合并至 hyper01 `/data04/jaxan/mw/runs/selector-v4-merged`(容器内
`/bigdata/mw/runs/selector-v4-merged`),用**相对符号链接**以便宿主与容器两个命名空间
都能解析(绝对链接在容器内会断)。
