# 收紧 drift cap 修不了均匀抬升——因为 cap 约束的语料里本来就没有它

> **结论:v6 cap 三臂的前提不成立。** 均匀抬升 +0.0092 出现在 **selector 的 set
> 打分语料**上,而 drift cap 约束的是 **DiD 语料 recent 臂**的 $A_r$,后者实测只有
> ±0.003、held-out 甚至跨零。$[|A_r|-\epsilon]_+$ 在 $\epsilon=0.02$ 下**恒为 0**,
> 整项没有梯度。**收紧一个已经≈0 的量,改不了长在别处的抬升。**

## 三个语境下的同名量,数值差一个量级

| 语境 | 均匀成分 | 来源 |
|---|---|---|
| DiD held-out(94 组,官方门控),v4 选中的 `lora-step250` | **−0.00079** [−0.0031, +0.0019]**(跨零)** | 本次重打 |
| DiD 训练集,v4 训练日志末 6 个窗口 | −0.0022 … +0.0035(±0.003) | `desktop-did-v4/hgkv/train.log` |
| **selector set 语料的 k=0 集合** | **+0.00917** [+0.0087, +0.0096] | `hgkv_k_stratified_v1` |

前两行是 cap 约束的对象,第三行是部署时实际被打分的对象。

## 排除了"两次运行的系统性偏移"这个替代解释

k 分层用的是两套独立打分语料相减(`selector-v4-merged` 挂 HGKV、
`selector-v4-frozen` 冻结)。若两次运行之间存在常数偏移,看起来就会像均匀抬升。

**判据:适配器的 no-history 路径号称与冻结逐位相同,所以 $U(\emptyset)$ 必须相等。**
实测全部 **5,335 个状态的 $U(\emptyset)$ 差值 mean = sd = 0.000000,0% 有差异**。
parity 精确成立 → 两套语料可直接相减 → **+0.0092 是真实的适配器效应**。

## 为什么原诊断会错

原文说"$\epsilon = 0.02$ 是 margin $m=0.01$ 的两倍,贴着 cap 加均匀抬升最省力",
并引论文 Table 3 的 $|A_r| = 0.0088$ 作交叉印证。**那个交叉印证是巧合**:
Table 3 的 0.0088 与 k 分层的 0.0092 不是同一个量(不同语料、不同打分管线),
而把 v4 适配器用官方门控重打后,同一位置的值是 −0.0008。

教训与 2026-08-01 的语料混杂同源:**两个数字接近,不等于它们测的是同一件事。**
交叉印证之前必须先确认量的定义与语料一致。

## 对目标函数的正确读法

$$\mathcal L = [m-(A_s-A_r)]_+ + [m-A_s]_+ + [m-(A_s-A_n)]_+ + \lambda_{\mathrm{cap}}\bigl([|A_r|-\epsilon]_+ + [|A_n|-\epsilon]_+\bigr) + \lambda\lVert\Delta W\rVert^2$$

- $[m - A_s]_+$ **奖励** $A_s$ 变大,而均匀抬升是把 $A_s$ 做大的最廉价方式;
- $\lambda_{\mathrm{cap}}$ 项**只**看 recent 臂与 wrong 臂两个特定构造,
  对"所有集合一起抬高"完全不设限。

**奖励在、约束不在**,所以模型走这条路。

## 修法(替换原来的"收紧 ε")

对**集合分布**设约束,而不是对两个特定臂:

1. **按状态中心化**:把 $\bar A(\text{state}) = \mathbb E_S[A(S)]$ 从所有臂里减掉,
   目标只看相对排序,均匀抬升在数学上**不可能得分**;
2. 或加罚项 $\lambda_{\bar A}\lvert\bar A\rvert$,直接压平均效应。

两者都需要每组多于一个稀疏臂才能估 $\mathbb E_S$ —— 这与**漏洞 2**(把三选一换成
候选池上的排序)需要的语料是同一份,应当**合并成一次改造**:
每决策点补打若干候选的冻结分(约 1 万次教师强制前向,四卡一小时内),
既提供排序目标,也提供中心化所需的 $\mathbb E_S$。

## 已跑的 v6 三臂怎么处理

不作为修法,只作为"该杠杆无效"的经验确认:预期 $A_r$ 无下降空间
(本来就≈0),而 `did_select` 可能因为 cap 在约 半数窗口上激活而略降。
`tightcap` 臂在 h00 因 **NCCL 集合通信超时(watchdog 600 s,SIGABRT)**
在 step 250 后挂掉、三次重试用尽,且卡随即被他人占用;鉴于前提已被推翻,
**不重发**,由 `midcap` / `nogain` 两臂给出经验确认即可。
